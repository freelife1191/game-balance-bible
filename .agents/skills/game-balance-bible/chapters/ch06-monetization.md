# 6장: 게임의 수익화

> 표기: 쪽 위치(`인쇄 N / PDF M` 또는 `인쇄 N쪽(PDF M)`)가 붙은 문장은 책의 서술이다. ‘스킬 정리’·‘스킬 보완’·‘스킬의 적용 지침’·‘스킬의 해석’ 표시 문장, **표 6.1의 재현 한계**·**상품표의 검산 조건** 문단의 위치 없는 해석·권고, 5단계 운영법 표의 ‘결정할 질문’·‘실패 신호’ 열, 압축 재구성 예시·핵심 개념·안티패턴·핵심 요약·연결은 이 스킬이 책을 바탕으로 정리한 적용 지침이다. 그 안에서도 위치가 붙은 문장은 책의 서술이다.

## 핵심 아이디어

저자는 게임 수익화를 단순한 매출 추출이 아니라 **원활하지 않은 경험을 완화하고, 육성 리듬을 조정하는 설계**로 둔다(인쇄 205–206 / PDF 235–236). 장르에 따라 결제의 역할은 다르다. 원문은 상호작용이 줄어 육성 자원이 부족해지는 MMORPG 유저에게는 수익화가 부족한 육성 자원을 보충하는 역할을 하고, 매일 플레이만 하면 필요한 육성 자원을 얻는 게임에서는 유저의 대기 시간을 줄이는 것이 수익화의 좋은 출발이 된다고 본다(인쇄 205 / PDF 235). 전체 흐름은 `수익화 포지셔닝 → 수익화 전략 → 수익화 검증`이다(인쇄 206 / PDF 236).

## 핵심 프레임워크

### 1. 수익화 포지셔닝: 경험 결제·성장 결제·기능 결제·화폐 결제

원문은 게임을 부가가치 서비스로 분류하고, 그 핵심을 비과금 유저에게는 기본 기능만 주고 더 나은 경험에는 결제를 받는 차별화된 경험으로 본다(인쇄 206 / PDF 236). 원문은 네 유형을 든다(인쇄 206–207 / PDF 236–237).

- **경험 결제**: 싱글플레이 구매나 시간제 이용권처럼 게임 경험권 자체를 판매한다.
- **성장 결제**: 캐릭터·장비의 육성 자원을 판매한다. 소프트 성장 결제는 과금/비과금 모두 진행 가능하되, 더 높은 등급의 캐릭터·더 시원한 경험을 제공하는 구조다(인쇄 206 / PDF 236). 원문 예는 <원신>에서 활성 유저는 4성 캐릭터, 과금 유저는 5성 캐릭터로 플레이하는 경우다(인쇄 206 / PDF 236).
- **기능 결제**: 자동 전투, 빠른 물약 구매 같은 편의를 제공하며 다른 결제와 묶이는 경우가 많다.
- **화폐 결제**: 주 화폐를 직접 판다. 기본 생산이 수요보다 부족할 때 빠른 획득 경로가 된다.

**판단 규칙**(스킬 정리): 상품을 먼저 고르지 말고, 어느 경험 마찰을 해결하는지와 어떤 운영 지표를 움직여야 하는지 먼저 정의한다. 원문은 수익화를 위한 수익화에 빠지지 말고, 게임 성장의 다양성·플레이의 재미와 지속성·난이도의 합리성을 우선 확보한 뒤 IP 가치와 아트 수준을 높이라고 한다(인쇄 223 / PDF 253). 스킬 정리: 수익화가 이 세 가지를 훼손하면 그 단기 매출은 장기 운영의 근거가 되지 않는다.

### 2. 기본 운영 지표와 과금 측정

스킬 정리: 아래 지표는 같은 관측 주기와 같은 활성 유저 정의로 맞춰 쓴다. 이탈률·활성 유저 결제율(PR)·ARPPU·ARPU·LTV·CPA의 정의는 원문 6.1.1절(인쇄 207–209 / PDF 237–239)에, 비용·수익·월 수익률 식은 표 6.1 노트(인쇄 211 / PDF 241)에 있다. `ARPU = PR × ARPPU`는 원문이 쓴 식이 아니라 두 정의와 표 6.1 값에서 성립하는 관계다(스킬 정리). 원문 이탈률 식의 분모는 ‘총 유저 수’이며, 예시는 월초 100명 중 월말 70명이 남으면 30%로 계산해 월초 유저 수를 분모로 쓴다(인쇄 207 / PDF 237).

```text
이탈률(CHURN) = 주기 중 이탈 유저 수 ÷ 총 유저 수
활성 유저 결제율(PR) = 과금 유저 수 ÷ 활성 유저 수
ARPPU = 주기 총 결제액 ÷ 과금 유저 수
ARPU = 주기 총 결제액 ÷ 활성 유저 수 = PR × ARPPU
CPA = 유저 1명 확보에 든 비용
비용 = 총 유저 수 × CPA
수익 = ARPPU × (총 유저 수 × PR)
월 수익률 = 수익 ÷ 비용 − 1
```

원문이 꼽는 이탈률의 중요한 주기는 2일·3일·1주·2주·1개월이다(인쇄 207 / PDF 237). ARPU는 보통 월 단위로 측정하고, 테스트 단계에서는 주 또는 일 단위로 측정하기도 한다(인쇄 209 / PDF 239). LTV는 주기 이탈률에 따라 주 또는 월 단위로 측정할 수 있다(인쇄 209 / PDF 239).

원문은 대다수 게임에서 과금 유저의 월 ARPPU가 게임 장르에 따라 결정되고, 같은 장르에서는 과금 유저의 월 평균 결제액이 거의 비슷하므로 결제율의 차이가 수익에 직접 영향을 준다고 쓴다(인쇄 208 / PDF 238). 같은 쪽의 ‘ARPPU 5만 원’은 결제율 계산을 보여 주는 가정이다(인쇄 208 / PDF 238). 스킬 정리: 원문은 장르별 월 ARPPU의 기준값을 제시하지 않으므로, 프로젝트의 ARPPU를 책의 수치와 맞대어 높다·낮다고 판정하지 않는다.

표 6.1은 유저 수 하나를 비용과 결제율 계산에 함께 쓰며 그 모집단을 정의하지 않는다(인쇄 211 / PDF 241). 스킬 정리: 위 단순 수익 모델의 ‘총 유저 수’는 PR의 분모와 같은 활성 모집단으로 맞춘다. 가입자 전체를 획득 비용의 기준으로 쓴다면 가입→활성 전환율을 별도로 넣어 비용과 수익의 모집단 차이를 반영한다.

원문은 운영 측면 생명주기를 `1 ÷ 이탈률`로 근사한다(인쇄 207 / PDF 237). 원문 본문의 LTV 식과 이 스킬이 표 6.1에 맞춰 읽는 식은 다음과 같다.

```text
원문 본문 식(인쇄 209 / PDF 239): LTV = 활성 유저의 평균 결제율 × (1 ÷ 주기 이탈률)
스킬의 해석(표 6.1과 단위 일치):  근사 LTV = ARPU × (1 ÷ 주기 이탈률)
```

예: 월 ARPU 40, 월 이탈률 80%이면 근사 LTV는 `40 × 1.25 = 50`이다. **원문 본문 수식에는 ‘활성 유저의 평균 결제율’이라고 적혀 있으나(인쇄 209 / PDF 239), 표 6.1의 40→50 계산과 단위가 맞으려면 ARPU를 사용해야 한다.** 표 6.1 노트의 월 LTV 식도 같은 문구를 쓰며(인쇄 211 / PDF 241), 본문은 LTV가 활성 유저의 평균 결제액과 유사하다고 설명한다(인쇄 209 / PDF 239). 원문은 이탈률로 예측한 생명주기가 참고용이며 실제 생명주기는 예측보다 훨씬 길다고 하고(인쇄 208 / PDF 238), 출시 후 시간이 갈수록 결제액이 줄어 실제 LTV가 균일하게 증가하지 않는다고도 한다(인쇄 209 / PDF 239). 원문 예시: 첫 주 LTV가 1만 원이고 유저 확보 비용이 3만 원이면 3주 차에 수익과 지출이 같아진다(인쇄 209 / PDF 239). 스킬 정리: 이 스킬은 실무 계산에서 ARPU를 사용하고, 근사 LTV는 주기당 ARPU와 이탈률이 일정하다는 단순 가정의 참고치로만 다룬다. 두 경고의 방향이 반대이므로 근사 LTV를 상한이나 하한으로 단정하지 않는다.

**표 6.1의 재현 한계**: 인쇄 211쪽(PDF 241)의 ARPU·LTV·비용·수익 열은 위 단순식으로 검산할 수 있으나 ‘손익분기점(월)’ 열의 산출식은 제시되지 않는다. 이탈률을 반영한 주기별 매출 경로와 신규 유입·비용 발생 시점이 정의되지 않은 상태에서 `CPA/ARPU`를 넣어 해당 열을 그대로 재현했다고 주장하지 않는다. 실제 회수 시점은 명시한 코호트의 누적 수익과 누적 비용을 비교해 구한다.

**과금 측정 절차**:

1. 경쟁·공공자원 비중을 고려해 단일 서버의 최적 유저 수를 정한다. 저자는 공공자원 비율이 높을수록 한 서버의 최적 유저 수가 작아진다고 판단하며, 서버 유저 수는 많을수록 좋지 않고 장르에 따라 달라진다고 한다(인쇄 210 / PDF 240). 원문 사례값은 경쟁 요소가 많고 공공자원을 두고 다투는 <미르의 전설> 같은 게임의 단일 서버 최적 유저 수 2,000명이며, 개인 경험과 유저 간 상호작용 중심의 모바일 게임 <몽환서유>의 최적 유저 수는 훨씬 많다(인쇄 210 / PDF 240).
2. 같은 장르 경쟁 게임의 CPA를 참고해 유저당 CPA를 가정한다(인쇄 210 / PDF 240). 스킬 보완: 채널·가입/튜토리얼 완료 같은 획득 기준을 고정한다(원문의 측정 기준 예는 인쇄 209 / PDF 239). 원문은 측정 기준의 단계가 늘어날 때마다 CPA도 가파르게 증가한다고 한다(인쇄 209 / PDF 239). 원문 사례값은 일반적인 CPA가 대략 3,700~55,500원, 같은 게임의 위챗 15,000원·다른 플랫폼 22,000원·광고 제휴 30,000원이며, 게임의 테마·장르·아트 스타일·경쟁 게임 수도 CPA에 직접 영향을 준다(인쇄 210 / PDF 240). 스킬 정리: 원문은 이 범위의 획득 기준을 밝히지 않으므로 프로젝트의 CPA를 이 범위와 맞대어 높다·낮다고 판정하지 않는다.
3. 월 이탈률, PR, ARPPU를 여러 시나리오로 둔다(인쇄 211 / PDF 241).
4. ARPU, LTV, 비용, 수익, 손익분기점을 한 표에서 비교한다(인쇄 211 / PDF 241).
5. 스킬 보완: 손익분기점이 지표 하나의 낙관값에만 의존하면, 그 지표를 목표가 아니라 리스크 가설로 관리한다.

### 3. 기본 형태: 일반 결제·유도 결제·뽑기 결제

- **일반 결제**: 상점에서 아이템·자원·아바타·패키지를 파는 기본 경로다. 원문은 초기에 가장 중요했던 일반 결제가 더 이상 주요 수익 모델이 아니며 상점은 수익화를 보충하는 형태라고 본다(인쇄 213 / PDF 243).
- **유도 결제**: 할인·한정·조건을 활용해 구매를 유도하는 프로모션 수단이다. 대표 형식은 첫 충전, 월간·주간 패스, 성장 패스, 시즌 패스, 보상 패키지, 누적 충전·소비, VIP, 10일 목표·순위 이벤트다(인쇄 213–215 / PDF 243–245). 원문은 유도 결제의 핵심을 할인 판매로 보고, 유도 결제가 점차 게임의 표준이 되어 비슷한 모델이 없는 것이 오히려 단점이 됐다고 한다(인쇄 213 / PDF 243). 다만 원문은 고품질 게임은 이런 ‘관행’을 무시할 수 있었다고 덧붙인다(인쇄 213 / PDF 243).
- **뽑기 결제**: 고가 아이템의 기대가치를 작은 단위의 시도로 나눠 파는 방식이다. 원문은 뽑기 결제를 복권을 판매하는 방식으로 규정하고(인쇄 212 / PDF 242), 이 판매 방식이 커버하는 유저층이 매우 넓어 게임 수익을 극대화하는 가장 좋은 방식이라고 본다(인쇄 216 / PDF 246). 원문은 뽑기 결제를 핵심 플레이가 수집인 카드 게임에서 가장 흔히 볼 수 있고 일부 ‘패스트푸드 웹게임’에서도 흔하다고 한다(인쇄 216 / PDF 246). 이 방식은 카드 게임처럼 유저군이 같은 콘텐츠를 서로 다른 품질의 조합으로 경험할 수 있을 때 적합하다(인쇄 216 / PDF 246). 원문 예는 기대가치 28만 원인 <원신> 5성 캐릭터를 1회 3천 원의 뽑기로 나눠 구매 거부감을 줄이는 경우다(인쇄 216 / PDF 246).

형식은 답이 아니다. 원문은 수익화 전략에서 중요한 것은 형식이 아니라 목적이라고 한다(인쇄 212 / PDF 242). 같은 쪽의 목적별 예는 결제율을 높이는 첫 충전 이벤트, ARPPU를 높이는 월간 패스·성장 패스 등이다(인쇄 212 / PDF 242). 월간 패스를 ARPPU를 높이는 예로 든 이 분류는 월간 패스의 가장 큰 목적을 리텐션으로 적는 인쇄 214쪽과 다르다(원문 표기, 인쇄 214 / PDF 244). 원문의 형식별 목표와 설계 조건은 다음과 같다.

- **첫 충전**: PR에 대응한다. 원문이 든 일반 권장 수익률은 4,000%로, 1,000원 결제에 40,000원 가치의 아이템을 준다는 뜻이다(인쇄 213–214 / PDF 243–244).
- **월간·주간 패스**: 가장 큰 목적은 해당 기간의 리텐션이고 과금 유저의 결제액도 높인다(인쇄 214 / PDF 244). 매일 로그인할 때마다 초과 보상을 주거나 차별화된 서비스 콘텐츠를 넣어 구매를 유도할 수 있다(인쇄 214 / PDF 244). 가격 차별로 페이백 금액·특권 대우에 따라 일반·프리미엄 월간 패스를 나눠 가격을 다르게 하며, 일반 유저는 둘 중 하나를 고르고 헤비과금 유저는 둘 다 살 수 있다(인쇄 214 / PDF 244). 원문이 든 설계 방식은 두 가지다. 보통은 일반 월간 패스의 수익이 프리미엄보다 높아 일반이 맛보기 상품, 프리미엄이 고급 상품이 되고, 다른 방법은 프리미엄의 수익과 가성비를 일반보다 훨씬 높게 잡아 더 많은 결제를 기대하는 것이다(인쇄 214 / PDF 244). 스킬 정리: 여기서 ‘수익’은 같은 쪽의 페이백 맥락에서 유저가 받는 보상 비율로 읽는다.
- **성장 패스**: 리텐션보다 활동에 중점을 두고 보통 유저 레벨을 기점으로 페이백한다. 일반적으로 과금 유저 그룹이 대상이라 비과금 유저는 참여할 수 없다(인쇄 214 / PDF 244).
- **시즌 패스**: 활동에 중점을 두되 과금·비과금 유저 모두 활동에 따라 보상을 받으며, 결제율과 평균 결제액을 크게 끌어올린다(인쇄 214–215 / PDF 244–245).
- **보상 패키지(한정 구매 패키지)**: 여러 게임 자원을 묶어 할인 판매하며, 구매 가능 간격에 따라 일일/주간/월간 보상 패키지, 평생 보상 패키지, 조건 보상 패키지 세 종류로 나뉜다(인쇄 215 / PDF 245). 결제액을 높이는 것이 목표이며 가장 설계하기 어려운 유도 결제 수단이므로, 특정 기간에 유저가 필요로 하는 자원을 미리 예측해 구매 의향을 높여야 한다(인쇄 215 / PDF 245). 가격 차별로 가장 싸고 가성비 좋은 패키지부터 단계별로 결제를 유도하면 유저가 구매력에 맞는 수량을 고르고, 대량의 패키지를 보고 거부감을 느끼는 상황을 막을 수 있다(인쇄 215 / PDF 245). 조건 보상 패키지는 특정 조건에 도달하면 푸시 알림으로 띄워 평균 결제액을 높이며, 원문 예는 40레벨 도달 때의 40레벨 장비 패키지, 첫 펫 획득 때의 그 펫 스킬북 할인이다(인쇄 215 / PDF 245).
- **누적 충전·누적 소비·VIP**: 지정 금액 도달 보상이나 특전 레벨로 평균 결제액을 높인다(인쇄 215 / PDF 245).

깊이 있는 게임에서 출시 초반의 과도한 수익화는 평판 하락과 유저 이탈로 서비스 종료를 앞당긴다는 것이 저자의 경고다(인쇄 212 / PDF 242). 반대로 빠른 비용 회수(‘패스트푸드’)가 기조라면 초반에 치열하게 수익화해야 한다. 게임을 장기 운영하려면 수익화 속도와 규모를 절제해 차근차근 추진해야 한다. 원문은 유도 결제의 종류와 지속성 유지를 양극단의 문제로 보고, 수익 모델 선택에 절충 방안이 없다고 한다(인쇄 212 / PDF 242).

### 4. 5단계 운영법

저자는 이벤트 운영의 5요소(목적·형식·참여 조건·주기·콘텐츠)로 이벤트 수익 모델을 검증하는 방법을 **5단계 운영법**이라 부른다(인쇄 216 / PDF 246). 아래 표의 요소는 원문(인쇄 216 / PDF 246)을, 주기 예는 원문(인쇄 218 / PDF 248)을 따르고, ‘결정할 질문’·‘실패 신호’ 열은 스킬 정리다.

| 요소 | 결정할 질문 | 실패 신호 |
|---|---|---|
| 이벤트 목적 | PR, 리텐션, 활동, ARPPU 중 무엇을 바꾸는가? | 상충 목표를 한 이벤트에 과도하게 넣음 |
| 이벤트 형식 | 월간 패스·시즌 패스·순위·10일 목표 중 어떤 참여 경험인가? | 목적과 무관하게 유행 형식을 복제함 |
| 참여 조건 | 어느 세그먼트가 몇 회 참여 가능한가? | 대상·횟수가 가치 제안과 맞지 않음 |
| 이벤트 주기 | 30분, 몇 시간, 몇 주 등 지속 시간은 무엇에 맞는가? | 보상 소모와 기간이 어긋남 |
| 이벤트 콘텐츠 | 목표·과정·보상·해결 경로는 명료한가? | 목표 달성 행동과 보상이 분리됨 |

원문은 시즌 패스를 결제율과 활동을 함께 노리는 다목적 이벤트의 예로 들면서, 목적이 많다고 좋은 것은 아니며 서로 상충하면 이벤트가 실패할 수 있다고 한다. 상충의 예는 리텐션율과 평균 결제액이다. 리텐션율을 높이려면 과금을 줄여야 하고, 과금을 늘리면 이탈률이 늘어난다(인쇄 217 / PDF 247). 원문은 다른 게임에서 효과가 좋았던 수익 모델을 목적을 파악하지 못한 채 가져오는 것도 경계한다(인쇄 212 / PDF 242). 스킬 정리: 5단계를 문서화하면 이런 복제를 막고, 사후 지표 변화도 원인별로 읽을 수 있다.

원문은 나머지 요소에도 예시와 조건을 든다. 형식은 신선할수록, 익숙한 형식이면 할인율이 높을수록 참여도가 높아지고, 사전예약·투표 같은 게임 외 형식도 있으며, 현장 뽑기 형식이면 참여할 수 있는 유저 수가 크게 줄어든다(인쇄 217 / PDF 247). 참여 조건은 대상 유저 그룹에 따라 나뉘어, 10일 목표는 모든 유저가 무료로 참여하고 첫 충전 보상은 과금 유저만 참여한다(인쇄 217 / PDF 247). 대부분의 이벤트는 주기 동안 한 번, 시간 제한 이벤트는 하루 한 번 참여할 수 있으며 이 횟수도 이벤트 효과에 직접 영향을 준다(인쇄 217 / PDF 247). 주기는 이벤트 콘텐츠에 따라 달라져 기본 이벤트는 30분, 시간 한정 푸시 알림 패키지는 몇 시간, 충전 이벤트는 몇 주 지속된다(인쇄 218 / PDF 248). 원문은 좋은 수익화 전략의 기준이 되는 답은 없고, 끊임없이 시도하고 분석하고 탐구해 맞는 열쇠를 찾는 방법이 가장 쉽다고 한다(인쇄 218 / PDF 248).

### 5. 수익화 검증: 충전 검증과 소비 검증

원문은 수익화 검증을 유저의 행동을 시뮬레이션해 게임의 수익화를 추론하고 검증하는 작업이라고 한다. 결제·소비 데이터를 주기별로 예측해 기본 데이터 지표와 비교하면 수익이 예측한 효과와 부합하는지 대략 판단할 수 있고, 게임 버전 최적화의 기본 데이터도 얻는다(인쇄 218 / PDF 248). 수익화 전략은 유저를 위해 결제 목표를 커스터마이징하는 일, 곧 과금 수준별 유저에 따라 최적의 결제 전략을 세우는 일이다(인쇄 218–219 / PDF 248–249). 원문은 결제 형태를 상품 구매와 화폐 구매로 나누고, 상품 구매는 충전에, 화폐 구매는 소비에 해당한다고 한다. 충전은 유저의 과금을 직접 유도하고 소비는 수동적으로 유도하므로, 수익화를 검증할 때는 충전과 소비를 검증하면 된다(인쇄 219 / PDF 249).

**충전 검증**은 현실 화폐로 직접 결제하는 모든 수익화 경로를 세그먼트별로 분류·집계한다(인쇄 219 / PDF 249). 원문은 기본 프로세스 표로 유저의 구매 경로에 따라 유저별 결제액을 집계하거나, 표를 집계하는 형식으로 과금 수준별 결제 데이터를 시뮬레이션할 수 있다고 하고 후자를 예로 든다(인쇄 219 / PDF 249). 각 상품에 `기본 형태, 대상 유저, 가격, 수익 비율(가성비), 세그먼트별 구매 여부`를 두고, 한 주기 동안 각 그룹이 사는 상품 가격을 합산한다(표 6.2의 열, 인쇄 220 / PDF 250). 그 뒤 세그먼트 비중을 곱해 예상 ARPPU를 구한다(표 6.3, 인쇄 220 / PDF 250). 표 6.2에 앞선 원문 가정 사례에서 저자는 소과금 유저가 성장 패스와 보상 패키지 1의 구매를 망설인다고 보고, 그 구매를 하게 하려면 가성비를 올리거나 실용성을 높이거나 가격을 낮추는 등 다른 방법을 써야 한다고 한다(인쇄 219 / PDF 249). 같은 사례는 소과금 유저의 결제액을 36 RMB, 중과금 유저의 결제액을 330 RMB로 추정한다(인쇄 219 / PDF 249).

원문은 1회 결제액으로 상품의 대상 그룹을 나눠 30 RMB 이하를 소과금, 30~98 RMB를 중과금, 98~648 RMB를 헤비과금 대상으로 가정한다(인쇄 220 / PDF 250). 다만 표 6.2의 푸시 알림 패키지 2는 128 RMB인데 대상이 중과금으로 표시돼 이 구간과 다르다(원문 표기). 원문 예시는 소과금 66 RMB, 중과금 398 RMB, 헤비과금 1,958 RMB에 비중 80%/16%/4%를 가정한다(인쇄 220 / PDF 250). 비중은 ‘2대 8 법칙’으로 과금 유저의 80%를 소과금, 나머지 20%의 80%(16%)를 중과금, 20%의 20%(4%)를 헤비과금으로 나눈 값이다(인쇄 220 / PDF 250).

```text
예상 ARPPU = 66×0.80 + 398×0.16 + 1,958×0.04 = 194.8 RMB
```

원문 인쇄 208쪽(PDF 238)은 결제액의 멱법칙 분포를 세그먼트별 계산의 배경으로 설명한다. 같은 쪽의 다른 가중 예시는 헤비과금 10%·10만 원, 중과금 40%·3만 원, 소과금 50%·3천 원으로 예상 ARPPU 23,500원을 얻는다(인쇄 208 / PDF 238). 스킬 정리: 일부 고액 과금 유저가 평균을 크게 움직일 수 있으므로 평균만 보지 말고 분포와 그룹별 결과를 함께 본다. 위 비중은 **과금 유저 안에서의 비중**이며 합계가 1이어야 한다. 전체 활성 유저 비중을 쓰려면 비과금 그룹의 결제액 0도 포함한 ARPU로 계산하고, PR을 다시 곱하지 않는다.

**상품표의 검산 조건**: 표 6.2(인쇄 220 / PDF 250)는 세그먼트별 구매 여부 열의 가격을 합쳐 66/398/1,958을 얻는다. 앞 쪽의 다른 사례(인쇄 219 / PDF 249)에는 `6+30+98+68`에 합계 330을 붙인 본문 불일치가 있다(실제 합은 202, 빠진 프리미엄 패스 128까지 포함하면 330). 앞 사례와 표 6.2는 상품명·가격·구매 목록도 달라 별개의 예시로 취급한다. 구매 확률·횟수가 있는 실제 프로젝트에서는 가격에 그 확률·횟수를 곱해 합산한다.

원문은 이 데이터가 참고용 기본 시뮬레이션이며 실제 헤비과금 비중은 생각보다 낮을 수 있다고 한다(인쇄 221 / PDF 251). 또 소과금과 중과금 중 어느 쪽 결제액을 늘리는 것이 수익에 도움이 되는지 보고 전략을 동적으로 조정한 뒤, 충전 검증으로 다시 확인하라고 한다(인쇄 221 / PDF 251). 스킬 정리: 각 그룹의 비중·구매 확률·상품 중복 구매를 독립 가설로 민감도 분석하고, 원문의 80/16/4 분포를 시장 일반 법칙으로 고정하지 않는다.

**소비 검증**은 게임 내 화폐로 상품을 사게 만드는 간접 결제 동력을 검증한다. 원문은 소비의 주요 동력을 목표가 유저에게 주는 압박과 보상이 유저에게 주는 유인력으로 보고, 표 6.4 노트는 이를 일으키는 방법이 예시 외에도 많다고 한다(인쇄 221 / PDF 251). 먼저 상품을 두 종류로 매핑한다.

- **압박(push)**: 경기장·순위·던전·주간 목표·기간 한정 뽑기, 그리고 ‘안 사면 손해’인 시간 제한 패키지와 ‘안 사면 없어짐’인 기간 한정 패키지처럼 목표가 주는 부족함이나 시간 제약으로 미는 동력(표 6.4, 인쇄 221 / PDF 251).
- **유인력(pull)**: 평생 한정 구매·프리미엄 패키지, 탈것·아바타처럼 ‘빨리 구매할수록 빨리 즐길 수 있음’이나 뛰어난 가성비 같은 보상이 끌어당기는 동력(표 6.4, 인쇄 221 / PDF 251).

그다음 세그먼트별로 `충전 검증으로 받은 다이아 − 필요 다이아 총액`을 계산한다. 표 6.5는 소과금의 충전 검증 획득 다이아 360, 가격 집계 670, **차액** −310을 함께 적는다(인쇄 222 / PDF 252). 스킬 정리: 위 식은 원문이 식으로 적은 정의가 아니라 이 값(`360 − 670 = −310`)에서 역산한 방향이며, 소과금의 부족량은 310다이아다. 원문은 충전 검증으로 얻는 다이아보다 소비에 더 많은 다이아가 필요하면 유저에게 다이아를 충전할 동력이 생긴다고 본다(인쇄 222 / PDF 252). 소비 검증도 1회 소비량으로 상품의 대상을 나눠 100다이아 이하를 소과금, 100~999다이아를 중과금, 1,000다이아 이상을 헤비과금 대상으로 본다(인쇄 222 / PDF 252). 다만 표 6.5의 대상 유저 열에는 이 구간과 어긋나는 행이 있다(원문 표기, 인쇄 222 / PDF 252). A 무기 500다이아는 헤비과금, 기간 한정 뽑기 1의 300다이아와 평생 한정 구매 1의 200다이아는 소과금으로 적혀 있다. 100다이아는 소과금과 중과금 구간에 모두 걸린다. 스킬의 적용 지침: 프로젝트에서는 경계값을 한쪽으로 정하고 대상 열을 구간식으로 다시 계산한다.

표 6.5(인쇄 222 / PDF 252)의 세 그룹 소비 행 합계 670/3,070/15,146은 직접 합산과 일치한다. 각각의 획득 360/2,280/14,800과 비교한 차액은 −310/−790/−346이다. 이 차액은 목표 상품의 전부 구매를 가정한 결과이며 실제 구매율·무료 공급·초기 잔고를 포함하는 구현에서는 그 입력을 별도로 추가한다.

저자는 이를 **나선형 계단 방식**으로 설명한다. 원문 예는 월간 패스·레벨업 패키지 등(7,000원)으로 300다이아를 얻은 ‘소액 결제 유저’(원문 표현)에게 360다이아가 필요한 더 좋은 보상을 두어 1,000원(60다이아)을 더 결제하게 한다. 이어 누적 결제 10,000원에 큰 보상을 주는 이벤트로 2,000원을 더 결제하게 하는 식이다(인쇄 222–223 / PDF 252–253). 원문은 충전과 소비의 두 나선형 구조를 겹겹이 쌓으면 소비 수준이 다른 유저들의 결제 금액을 크게 끌어올릴 수 있다고 본다(인쇄 223 / PDF 253). 스킬 정리: 이 방식은 결제 증가를 설명하지만, 무리한 결핍·FOMO(놓칠까 봐 느끼는 불안)는 이탈·불신을 만들 수 있으므로 결제 전후의 승률, 잔여 자원, 리텐션을 함께 검증한다.

## 압축 재구성 예시

**원문 수치 재사용과 설명용 운영 가정의 구분**

아래 66/398/1,958 RMB와 80%/16%/4%는 원문의 충전 검증·가중 ARPPU 예시를 재사용한다. ‘신규 유저 PR’, 7일 기간, 즉시 보상+매일 보상은 5단계 운영법 적용을 보여 주기 위해 추가한 가상 운영안이다.

1. 목표를 ‘신규 유저 PR 상승’으로 하나만 둔다.
2. 첫 충전 상품을 소과금 세그먼트에, 월간 패스를 리텐션이 필요한 활성 과금 유저에 배치한다.
3. 5단계 운영법으로 참여 조건(첫 결제 1회), 기간(7일), 콘텐츠(즉시 보상+매일 보상)를 쓴다.
4. 원문 예시의 세그먼트별 구매 목록을 합산한다. `66, 398, 1,958`과 비중 `80%, 16%, 4%`라면 예상 ARPPU는 194.8이다.
5. 같은 세그먼트의 화폐 소비표에서 `획득 − 필요`가 −310인지, 즉 310다이아가 부족한지 본다. 부족분을 곧바로 가격 인상 근거로 삼지 않고, 해당 부족이 유저가 선택한 도전과 목표에서 생겼는지, 무료 진행을 막지 않는지 검토한다.

## 핵심 개념

- **PR(활성 유저 결제율)**: 활성 유저 중 과금 유저의 비율.
- **ARPPU / ARPU**: 과금 유저당 / 활성 유저당 주기 평균 결제액. `ARPU = PR × ARPPU`.
- **CHURN과 리텐션**: 주기 이탈 비율과 남아 있는 비율. 분모·코호트·관찰 주기를 고정한다.
- **CPA**: 획득 기준을 명시한 유저 1명당 확보 비용.
- **LTV**: 반복 결제·이탈을 고려한 유저 가치. 원문의 단순 근사는 참고용이다.
- **가격 차별**: 같은 범주의 상품을 구매력·특전에 따라 여러 가격대에 배치하는 방식.
- **직접 충전 / 간접 소비**: 현실 화폐로 상품을 직접 사는 충전과, 현실 화폐로 게임 내 화폐를 사서 그 화폐로 상품을 사는 소비다. 충전은 과금을 직접, 소비는 수동적으로 유도한다(인쇄 219 / PDF 249).
- **압박(push) / 유인력(pull)**: 부족·제한으로 밀거나, 가치·보상으로 끌어당기는 소비 동력.

## 안티패턴

- **수익화를 최우선 목적화**: 재미·성장·난이도보다 결제 경로를 먼저 최적화하는 방식.
- **지표 정의 혼용**: 신규 가입자를 분모로 한 결제율과 활성 유저를 분모로 한 ARPU를 같은 표에서 섞는 방식. 원문 PR 식의 분모는 활성 유저지만, 같은 쪽 예시는 프로모션으로 확보한 100명을 분모로 쓴다(인쇄 208 / PDF 238). 이 안티패턴은 스킬의 적용 지침이며 원문 예시를 위반 사례로 판정하지 않는다.
- **형식 복제**: 성공 사례의 패스·뽑기·푸시 패키지를 목적·대상·주기 없이 가져오는 방식.
- **헤비과금 가정 고정**: 낙관적인 헤비과금 비중 하나로 ARPPU·손익분기점을 확정하는 방식.
- **강제 결핍 설계**: 핵심 진행을 막는 부족과 과도한 시간 제한으로 차액만 키우는 방식.
- **수익률만 보고 판정**: 결제액 상승 뒤 이탈·승률·공정성·콘텐츠 소모를 확인하지 않는 방식.

## 핵심 요약

1. 수익화의 설계 단위는 상품이 아니라 해결하려는 경험 마찰과 운영 목표다.
2. PR, ARPPU, ARPU, 이탈률, CPA는 같은 주기·코호트 정의에서만 비교할 수 있다.
3. 5단계 운영법은 이벤트의 목적, 형식, 대상, 기간, 보상이 서로 맞는지 검증한다.
4. 충전 검증은 직접 매출 가설을, 소비 검증은 게임 안에서 생기는 간접 결제 동력과 화폐 차액을 검증한다.
5. 매출 예측은 가정의 집합이다. 세그먼트 비중과 구매 확률을 실제 데이터로 반복 보정해야 한다.

## 연결

- **4장**: 화폐 생산·소비 구조가 간접 소비 동력과 상품 가치를 제한한다.
- **5장**: 판매 자원과 화폐 구매가 레벨·전투력·잔여 자원·PvP 격차를 바꾸므로 사전 검증한다.
- **7장**: 이벤트 목적과 단계별 유저 목표·콘텐츠 리듬을 연결해 운영한다.
