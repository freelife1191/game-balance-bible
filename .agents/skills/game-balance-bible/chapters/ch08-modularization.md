# 8장: 수치 모듈화

> 표기: `(인쇄 N / PDF M)`이 붙은 문장은 책의 서술이다. ‘스킬 정리’·‘스킬의 적용 지침’·‘스킬 검산’ 표시 문장과 **왜 작동하는가 / 실패 모드**, 핵심 개념·핵심 요약·연결의 압축 정리는 이 스킬이 책을 바탕으로 정리한 것이며, 그 안에서도 위치가 붙은 문장은 책의 서술이다.

## 핵심 아이디어

**수치 모듈화**는 게임의 기능·플레이·성장을 이루는 수치 구조를 독립적으로 설계하고 집중 관리하는 방식이다. 핵심은 모든 수치를 **수치 모델**로 만드는 데 있다(인쇄 239 / PDF 269). 원문은 수치 모델이 독립성과 통합성을 함께 갖는다고 한다(인쇄 239 / PDF 269). 스킬 정리: 실제 게임 경험은 모델 간 연결에서 생기므로, 모델을 독립적으로 설계하더라도 통합성을 보존해야 한다. 원문은 수치를 최적화할 때 어느 한 부분만 최적화하거나 모든 수치 구성을 조정해서는 안 되고, 경험이 좋지 않은 수치 모델을 최적화해야 한다고 한다(인쇄 240 / PDF 270). 또 수치 모듈화의 중요한 역할을 전체에 영향을 주지 않고 그 모델을 빠르게 포지셔닝·최적화하는 데 둔다(인쇄 240 / PDF 270). 스킬의 적용 지침: 그 모델을 고칠 때는 연결된 모델에 미치는 영향을 확인한다.

저자는 머리말에서 8장을 수치 기획자들의 미래에 새로운 설계 아이디어와 발전 방향이 되기를 바라며 게임 수치에 대한 개인적인 생각과 경험을 설명한 장이라고 밝힌다(머리말, 인쇄 xxv / PDF 27). 스킬 정리: 이 장의 서술은 저자의 실무 경험에 근거한 관점으로 다루며, 그림 8.2처럼 저자가 개인 견해라고 밝힌 부분은 업계 공통 규범으로 일반화하지 않는다.

## 수치 모델의 범위와 계약

수치 모델은 변수, 등식, 부등식, 수학적 연산, 언어 규칙으로 대상의 특징과 내부 연결성을 설명한다(인쇄 240 / PDF 270).

- **넓은 의미의 수치 모델**: 특정 콘텐츠의 모델 집합. 예: 전투 기본 모델, 성장 모듈 육성 모델, 몬스터 난이도 모델을 아우르는 전투 모델(인쇄 240 / PDF 270).
- **좁은 의미의 수치 모델**: 독립된 한 모델. 예: 전체 생산 모델, 드롭 모델(인쇄 240 / PDF 270).
- **독립성**: 모델과 모델 간 콘텐츠가 서로 독립된 성질(인쇄 239 / PDF 269).
- **통합성**: 속성 정의가 성장 모델의 기반이 되고, 공식이 속성의 척도가 되는 것처럼 모델들이 서로 영향을 주며 하나의 경험을 만드는 성질(인쇄 239 / PDF 269).

원문은 수치 모델을 연결하려면 수치를 모듈화해야 하고, 각 수치 모델이 인터페이스·함수·로직·상태라는 기본 속성을 가져야 하며, 그중 기능·상태·인터페이스는 외부 특성을, 로직은 내부 특성을 반영한다고 한다(인쇄 251 / PDF 281). 같은 문단에서 ‘함수’와 ‘기능’이 번갈아 쓰인다. 스킬 정리: 각 모델에 이 외부·내부 특성을 명시하면 모듈 간 전달 데이터와 변경 영향의 경계가 생긴다.

가장 단순한 성장 모델도 명시적으로 쓴다.

`공격력 = 초깃값 매개변수 + (레벨 - 1) × 레벨 증폭 매개변수`

예를 들어 초깃값 100, 레벨 증폭 50이면 레벨 10의 공격력은 550이다. 초깃값과 증폭값은 상수, 레벨은 독립변수다(인쇄 240–241 / PDF 270–271). 스킬의 적용 지침: 단순한 식이라도 어떤 입력이 어떤 결과를 바꾸는지 추적할 수 있어야 한다.

원문 표 8.1(인쇄 240 / PDF 270)은 이 예시의 입력을 `초깃값 매개변수 100`, `레벨 증폭 매개변수 50`으로 분리해 적는다. 표 8.2(인쇄 241 / PDF 271)는 같은 식의 결과를 레벨 1·10·50·100에서 각각 `100 / 550 / 2,550 / 5,050`으로 검산한다. 스킬 정리: 이 두 표는 복잡한 성장 곡선을 권장하려는 것이 아니라, **매개변수 표와 산출값 표를 분리해 한 식의 입력·출력을 추적**하는 예로 읽는다.

## 핵심 프레임워크: 수치 모델 10단계

원문은 수치 모델 구축 프로세스를 10단계로 정리하고 단계마다 모델·소속·역할을 설명한다(1~4단계 인쇄 242 / PDF 272, 5단계 인쇄 242–243 / PDF 272–273, 6~9단계 인쇄 243 / PDF 273, 10단계 인쇄 243–244 / PDF 273–274).

| 단계 | 모델 | 소속 | 핵심 산출물·검증 |
|---|---|---|---|
| 1 | 기초 성장 모델 | 전투 | 레벨 성장 등 게임 생명주기·리듬·경험 주기의 기초 |
| 2 | 속성 성장 모델 | 전투 | 직업별 표준 속성 성장 경험, 전투 기본 모델로 1차 밸런스 |
| 3 | 성장 모듈 성장 모델 | 전투 | 속성 분배 모델 조합으로 각 육성 모듈에 1단계 속성을 배분 |
| 4 | 몬스터 난이도 모델 | 전투 | 유저 성장에 대응하는 적 데이터셋; 성장 검증 후 재보정 |
| 5 | 성장 소비 모델 | 경제 | 성장 모듈과 1:1 대응하는 비용과 육성 가성비 |
| 6 | 생산 모델 | 경제 | 모든 플레이의 생산량; 고정 생산 / 랜덤 생산 구분 |
| 7 | 경제 검증 모델 | 검증 | 생산 검증(모든 플레이 생산 집계)·소비 검증(주기 내 각 성장 모듈의 올릴 수 있는 레벨을 고정해 소비 산출)·주기별 자원 잔여량 |
| 8 | 성장 검증 모델 | 검증 | 생산 검증의 자원 데이터를 인덱싱·계산한 각 주기의 실제 성장 데이터; 성장 경험과 몬스터 난이도 검증 근거 |
| 9 | 수익화 검증 모델 | 수익화 | 수익화 전략 집계와 주기별 수익 예측 |
| 10 | 전투 기본 모델 | 전투 | 직업 밸런스와 단계별 몬스터 난이도 검증 |

8.3절은 같은 수치 구조를 기초 성장·속성 성장·속성 분배·성장·몬스터 난이도·소비·생산 분배·생산·검증·기본 전투의 10개 **모듈**로 다시 나열한다(인쇄 250–251 / PDF 280–281). 스킬 정리: 이 모듈 목록은 위 10개 모델과 1:1이 아니다. 속성 분배·생산 분배가 별도 모듈로 나뉘고, 8.3절 목록에는 검증 모듈 하나만 있으며 수익화 모듈은 따로 없다. 모델 7·8·9의 소속(검증·검증·수익화)은 8.1절 본문 기준으로 읽는다.

### 의존 순서와 피드백 루프

원문 그림 8.1(인쇄 241 / PDF 271)은 네 상위 분류(전투·경제·검증·수익화)와 10개 모델을 한 선형 파이프라인이 아니라 **연결망**으로 그린다. 모델 1에서는 `생산 분배 모델 조합`이 갈라져 생산 모델(모델 6)로 향하고, 모델 1→2 뒤에는 `속성 분배 모델 조합`이 A/B/C 성장 모듈(모델 3)로 나뉜다. 모델 7은 생산 집계를 받아 `생산 검증 → 소비 검증`을 수행하고, 그 결과의 `자원 잔여 비율`은 충전 검증·소비 검증(그림의 모델 9)에 연결된다. 모델 7의 선과 모델 3(A/B/C)의 선은 모델 8로 들어가고, 모델 8은 `레벨 검증 → 육성 검증`을 거쳐 모델 4로 이어진다. 모델 2의 선은 첫 번째 밸런스로, 모델 4와 8의 선은 두 번째 밸런스로 모델 10(전투 기본 모델)에 합류한다. 그림에는 모델 5(성장 소비 모델)에서 모델 1(기초 성장 모델)로 향하는 화살표도 있으나 본문은 이 연결을 따로 설명하지 않는다(인쇄 241 / PDF 271).

텍스트로 읽는 기본 순서는 모델 1→2→3으로 유저 성장의 기준과 분배를 정하고, 모델 4는 그 성장의 피드백으로 적 난이도를 만든다(인쇄 242 / PDF 272). 모델 5의 소비는 모델 3의 성장 수익과 1:1로 대응하며(인쇄 242 / PDF 272), 모델 6은 성장 주기의 소비 데이터를 바탕으로 모든 플레이의 생산 데이터를 설정한다(인쇄 243 / PDF 273). 원문은 생산 모델이 각 플레이의 수익에 직접 영향을 주고, 수치 측면에서 각 플레이에 대한 유저의 선호도를 결정한다고 한다(인쇄 243 / PDF 273). 모델 7은 `생산 - 소비 = 주기별 자원 잔여`로 각 주기 유저의 성장 원동력과 생존 압박을 미리 판단한다(인쇄 243 / PDF 273). 모델 8은 모델 7의 생산 검증에서 얻은 자원 데이터를 인덱싱·계산해 각 주기의 성장 데이터를 구하고, 이것이 유저 성장 경험과 몬스터 난이도 데이터를 검증하는 근거가 된다(인쇄 243 / PDF 273). 모델 9는 수익화 전략을 집계·계산해 주기별 수익을 예측한다(인쇄 243 / PDF 273).

스킬 정리: 번호 순서는 설계 편의를 위한 기본값이다. 원문도 모델 4는 처음에는 성장 검증 데이터가 없으므로 각 모듈의 성장 모델 데이터로 기본 데이터를 만들고, 성장 검증 모델이 완성되면 그 데이터를 대입하라고 한다(인쇄 242 / PDF 272). **모델 10(전투 기본 모델)은 특정 시기에 구축할 필요 없이 필요에 따라 구축하는, 검증에 쓰는 전투 모델**이며, 원문은 기본 속성 성장과 성장 검증을 이 모델로 반드시 검증하라고 한다(인쇄 243–244 / PDF 273–274).

## 수치 모델 구축의 3단계

저자는 수치 모델 구축을 먼저 아이디어를 구상하고, 세부 사항을 보강한 다음, 구상을 모델링하는 과정으로 설명한다(인쇄 244 / PDF 274). 원문 예시에서는 육성 수익이 레벨에 따라 단계적으로 느는 독립 성장 모듈이라는 아이디어로 성장 모듈의 성장 모델을 설계한다. 이어 레벨업에 재료를 소비하고 일정 레벨마다 돌변하는 느낌과 새 자원이 필요하다는 발전된 아이디어로 성장 소비 모델을 설계한다. 소비를 확정한 뒤에는 성장 모듈에서 생산하는 자원을 분배해 경제 사이클을 설계한다(인쇄 244 / PDF 274). 원문은 성유물 예시를 들며 수치 모델 구축의 1단계를 기능의 세부 사항을 요약하고 설계 아이디어를 명확히 하는 일로 둔다. 또 이 정리는 게임 기획안의 내용이 아니라 ‘브레인스토밍 단계’나 수치 기획안 작성 때 나열하는 아이디어라고 밝힌다(인쇄 244–245 / PDF 274–275). 아이디어를 명확히 한 뒤 8.2.1~8.2.3절의 세 단계로 수치를 구한다(인쇄 245–250 / PDF 275–280). 스킬 정리: 앞의 ‘구상 → 보강 → 모델링’과 아래 세 단계는 원문이 1:1로 대응시킨 구분이 아니다.

1. **매개변수 정의** — 정리한 아이디어에 따라 수치 모델의 매개변수를 정의하며, 매개변수는 계산 방법과 결과에 직접 영향을 준다(인쇄 245 / PDF 275). 스킬의 적용 지침: 선택지, 상한, 희귀도, 슬롯, 확률, 성장 횟수처럼 결과에 직접 영향을 주는 변수를 빠뜨리지 않는다.
2. **데이터 호출** — 다른 수치 모델 계산에서 얻은 데이터를 기준 수치로 참조한다. 예를 들어 성유물의 속성 총량은 `속성 성장 데이터 × 성유물 속성 비율`로 가져온다(인쇄 247 / PDF 277). 스킬의 적용 지침: 독립 모델이라고 임의 기준을 새로 만들지 않는다.
3. **모델 계산** — 정의한 매개변수와 호출한 속성 수치로 별 등급별 주 속성, 레벨업 후 주 속성, 부속성 풀의 값을 공식으로 계산하고(인쇄 247 / PDF 277), 구한 수치를 표에 넣어 설계를 마친다. 원문은 세트 효과처럼 남은 개념도 같은 세 단계로 계속 개선한다고 한다(인쇄 250 / PDF 280). 스킬의 적용 지침: 결과는 다음 모델이 사용할 수 있는 표로 고정한다.

### 원문 성유물 예시: 재현 가능한 입력과 계산

아래는 원문이 <원신> 성유물로 설명한 **책의 설계 예시**다(인쇄 244–249 / PDF 274–279). 현재 게임의 실제 규칙·확률·수치라고 가정하지 않는다. 예시의 목적은 무작위 성장 모듈을 `규칙 → 입력 표 → 호출 데이터 → 산식 → 결과 표`로 완결하는 방법을 보이는 데 있다.

#### 1. 규칙과 풀의 스키마

- 장착 부위는 5개다. 주 속성과 부속성은 같은 속성이 중복되지 않으며, 주 속성은 최대 1개·부속성은 최대 4개다(설계 아이디어 1~3, 인쇄 244 / PDF 274).
- 1·2부위의 주 속성은 각각 공격력·HP로 고정하고, 3~5부위의 주 속성은 속성 풀에서 랜덤으로 선택된다(인쇄 244–245 / PDF 274–275). 원문 노트는 1·2부위의 공격력·HP가 가장 기본적인 속성으로 정상적인 게임 경험을 보장하고 극단적인 육성 전략이 밸런스를 깨지 않게 한다고 한다(인쇄 246 / PDF 276). 또 3~5부위는 보편적이고 고유한 속성을 두어 부위 특성을 차별화하고, 고유 속성의 출현 확률을 높여 유저가 원하는 속성을 빠르게 얻도록 돕는다고 한다(인쇄 246 / PDF 276). 원문 표 8.3의 주 속성 출현 횟수는 `공격력 1, 방어력 0, HP 1, 공격력% 3, 방어력% 3, HP% 3, 원소 마스터리 3, 원소 충전 효율 1, 원소 피해 보너스 1, 물리 피해 보너스 1, 치명타 확률 1, 치명타 피해 1, 치유 보너스 1`이다(인쇄 245 / PDF 275).
- 부속성 풀은 부위·주 속성에 따라 제외 항목이 생긴다. 원문 표 8.4의 **출현 횟수**는 공격력 4, 방어력 5, HP 4, 공격력% 4, 방어력% 4, HP% 4, 원소 마스터리 4, 원소 충전 효율 4, 치명타 확률 4, 치명타 피해 4다. 원소 피해·물리 피해 보너스 열은 체크와 총합이 모두 빈칸이고, 치유 보너스 열은 체크 없이 총합만 4로 인쇄돼 있다. 원문 노트는 주 속성에서 나온 속성이 부속성에서 다시 나오지 않는다는 설계 아이디어 2에 따라 랜덤 속성이 나오는 최대 횟수에서 1을 빼서 집계한다고 한다(인쇄 246 / PDF 276). 스킬 검산: 방어력은 표 8.3에서 주 속성 출현 횟수가 0이므로, 부속성 총합 5는 1을 빼지 않은 값으로 읽힌다. 치유 보너스 부속성은 표 8.8에서 0.0%이고 표 8.11에는 열은 있으나 값이 비어 있어(인쇄 247·249 / PDF 277·279), 표 8.4의 총합 4와 맞지 않는다.
- 별 등급은 1~5성이고 올릴 수 없다(인쇄 244–245 / PDF 274–275). 원문 예시의 주 속성 비율은 `60/70/80/90/100%`, 부속성 비율은 `20/40/60/80/100%`다(표 8.6, 인쇄 246 / PDF 276). 원문 노트는 등급 간 주 속성 차이가 너무 크지 않아야 초반 게임 경험에 도움이 되고, 부속성 차이는 더 커야 후반에 높은 별 등급이 필요해진다고 한다(인쇄 247 / PDF 277). 최대 레벨은 `별 등급 × 4`(인쇄 245 / PDF 275), 5성 초기 속성 비율은 15%, 돌파 가능 횟수는 5회다(표 8.5, 인쇄 246 / PDF 276). 돌파 가능 횟수는 레벨을 올릴 때 부속성을 증가시킬 수 있는 횟수다(인쇄 246 / PDF 276). 원문 노트는 15%가 속성 분배에서 정한 성유물 시스템의 기초 속성 비율을 기준으로 하며 여러 성장 모듈의 가중치에 따라 늘거나 줄 수 있다고 한다(인쇄 246 / PDF 276).
- 4레벨마다 속성이 4개 미만이면 부속성 1개를 반드시 추가한다. 이미 4개면 4개 중 하나를 무작위 강화한다(설계 아이디어 6·7, 인쇄 245 / PDF 275). 원문은 연속 강화가 ‘꽤 높은 확률’로 일어날 수 있다고만 하며, **선택 확률이나 가중치는 제시하지 않는다**. 따라서 독립 균등 추첨 확률을 이 예시에 덧붙이면 안 된다.
- 부속성 변동 구간은 70%, 80%, 90%, 100% 네 단계이며, 설계 아이디어 6에 따라 같은 별 등급에서 최소 4개의 다른 속성 변동 범위가 필요해 네 구간을 두었다(표 8.7, 인쇄 247 / PDF 277). 구간 간격을 넓히면 원하는 완벽 속성이 나올 확률이 낮아지고, 좁히면 육성 경험이 완만해진다는 것이 원문의 설계 판단이다(표 8.7, 인쇄 247 / PDF 277).

#### 2. 호출 데이터와 대표 검산

원문 표 8.8은 다른 성장 모델에서 호출한 속성 총합 중 주 속성 공격력 311, 부속성 공격력 388을 쓴다(인쇄 247 / PDF 277). 주 속성 초깃값은 다음처럼 계산한다(인쇄 248 / PDF 278).

`초기 속성 = 5성 초기 비율 × 별 등급 주 속성 비율 × 속성 총합 ÷ 속성 출현 횟수`

따라서 5성 1부위 공격력은 `15% × 100% × 311 ÷ 1 = 46.65`, 원문은 이를 반올림해 47pt로 제시한다(인쇄 248 / PDF 278). 스킬 검산: 표 8.9는 3~5부위 원소 마스터리를 84.15로 싣는데(인쇄 248 / PDF 278), 이는 표 8.8의 주 속성 원소 마스터리 561(인쇄 247 / PDF 277)을 출현 횟수 1로 나눈 `15% × 100% × 561 ÷ 1`과 같다. 표 8.3의 출현 횟수 3(인쇄 245 / PDF 275)으로 공식을 적용하면 28.05이므로, 재현할 때는 원문 표기 84.15와 공식 계산값 28.05를 구분한다. 부속성 풀의 최댓값은 다음과 같다(인쇄 249 / PDF 279).

`부속성 최댓값 = (별 등급 부속성 비율 × 속성 총합) ÷ (속성 출현 횟수 × 돌파 가능 횟수)`

5성 공격력 부속성의 경우 `(100% × 388) ÷ (4 × 5) = 19.4`이며, 원문 표는 반올림한 19pt를 싣는다. 스킬 검산: 이 식의 출현 횟수 4는 표 8.4의 공격력 부속성 출현 횟수와 같고(인쇄 246 / PDF 276), 원문 노트는 5성 공격력에 `(4 × 5)`를 쓴다(인쇄 249 / PDF 279). 실제 한 번의 부속성 값은 이 최댓값에 변동 범위를 곱해 구성하며(인쇄 249 / PDF 279), 변동 범위는 1~4단 70/80/90/100%다(표 8.7, 인쇄 247 / PDF 277). 적용 후 반올림 규칙은 원문이 명시하지 않으므로 프로젝트 구현에서 별도로 고정해야 한다.

#### 3. 레벨 표를 재현할 때의 주의

원문 표 8.10은 5성에서 초기 15%, 레벨 1의 19.25%, 레벨 15의 78.75%, 레벨 20의 100.00%를 제시한다(인쇄 248–249 / PDF 278–279). 표는 1~4성 열도 20레벨까지 채우지만 최대 레벨은 `별 등급 × 4`이므로, 1~4성의 최대 레벨을 넘는 행은 원문 규칙과 맞지 않는다. 원문 표의 초기 속성 행은 1~4성을 `9% / 11% / 12% / 14%`로 싣는다(인쇄 248 / PDF 278). 스킬 검산: 이 값은 `15% × 별 등급 주 속성 비율`(9%·10.5%·12%·13.5%)을 반올림한 것으로 읽히며, 각 열은 `초기 비율 + (1 - 초기 비율) ÷ 20 × 현재 레벨 × 별 등급 주 속성 비율`로 재현된다. 5성 열은 `15% + ((1 - 15%) ÷ 20 × 현재 레벨 × 100%)`, 2성 1레벨은 `10.5% + 89.5% ÷ 20 × 1 × 70% = 13.63%`다. 이 식은 **표의 누적 속성 비율을 재현한 식**이다. 원문에 인쇄된 ‘레벨당 업그레이드 비율’ 표기는 초기 비율을 더하는 표현을 생략하므로, 구현에서는 `초깃값`, `레벨당 증가분`, `표시 누적값`을 분리해 검산한다. 예컨대 표의 5성·15레벨 공격력은 `78.75% × 311 = 244.9125`이며 원문은 245로 제시한다(인쇄 249 / PDF 279).

이 예시의 산식은 입력 표의 출현 횟수·별 등급 비율·돌파 횟수에 의존한다. 어느 하나를 바꾸면 초기 주 속성, 부속성 풀, 레벨 표를 함께 다시 계산해야 한다.

## 왜 작동하는가 / 실패 모드

- **왜 작동하는가**: 문제 경험을 특정 모델로 포지셔닝하고, 입력·출력·연결을 보며 전체를 무너뜨리지 않고 조정할 수 있다.
- **실패: 모든 숫자를 한 번에 조정** — 원인을 찾지 못하고 회귀를 키운다. 유저 경험이 나쁜 모델을 먼저 특정한다.
- **실패: 독립성을 고립으로 오해** — 소비 모델의 비용을 바꿔 놓고 생산·성장·수익화를 재검증하지 않으면 통합성이 깨진다.
- **실패: 감각으로만 수치 결정** — 원문은 게임의 수치 시스템이 각기 다른 수치 모델을 계산해 이뤄지며, 느낌에 의존해 갑자기 떠오르는 것이 아니라고 한다(인쇄 240 / PDF 270). 스킬의 적용 지침: 가설도 변수·등식·표로 표현해 검증 가능하게 만든다.
- **실패: 모듈을 재사용하지 않음** — 요구 사항마다 새 표를 만들면 속도만 빨라지고 수치 경험은 축적되지 않는다(인쇄 251 / PDF 281). 유사한 시스템은 모델의 계약과 검증 절차를 계승한다.

## 모듈화의 운영 원칙

원문은 자동차가 여러 제어 모듈로 이뤄지며 각 모듈은 독립적이지만 모두 모여 하나의 완전한 자동차가 된다고 하고, 수치 모듈의 원리도 이와 같다고 한다(인쇄 250–251 / PDF 280–281).

원문은 콘텐츠 업데이트로 모듈별 수치가 기하급수로 늘어나므로, 표준이 되는 수치 모델을 만들어 버전 업데이트에 따른 기능 변화와 경험 최적화에 신속하게 대응하라고 한다(인쇄 251 / PDF 281). 저자는 ‘어떤 게임의 어떤 모듈을 복각하라’는 요구가 잘못된 방법이 아니며, 때로는 어떤 수치를 완벽하게 복각하는 것이 우수한 게임 경험을 계승하고 자신의 수치 감각을 높이는 방법이 된다고 본다(인쇄 251 / PDF 281). 사례로 <원신>의 성유물 시스템은 <서머너즈 워: 천공의 아레나>의 룬 시스템을 개선한 것이고 <음양사>에도 쓰였다고 들며, 좋은 게임 경험에 반드시 독창성이 필요하지는 않다고 한다(인쇄 251–252 / PDF 281–282). 스킬의 적용 지침: 복각할 때는 숫자와 함께 그 모듈이 만든 경험과 인터페이스·제약·검증 순서를 기록해 두어야 다음 프로젝트의 연결 조건에 맞춰 계승할 수 있다.

원문 그림 8.2(인쇄 250 / PDF 280)는 중국 게임 산업의 PC 게임(2002~2009)·PC 웹 게임(2009~2013)·모바일 게임(2013~2020)·멀티 플랫폼(2020+) 시대를 수치 생산 방식의 변화와 나란히 둔 **저자의 발전 관점**이다. 생산 방식은 `수작업 계산(2002~2010) → 조립 라인 방식(2010~2015) → 플랫폼 생산(2015~2018) → 모듈화 생산(2018+) → 인공지능(AI) 시대(2025+)`로 이어진다. 이는 모듈화를 반복 가능한 생산 방식에 비유하는 맥락 자료이며, 현행 산업 분류·미래 예측·AI 도입의 근거로 사용하지 않는다.

수치 기획자에게 필요한 것은 방법이 아니라 **아이디어와 검증**이며, 수치 검증과 시각화로 경험을 검증하고 정식 출시 전에 수치 구조의 밸런스와 안정성을 검증할 방법을 생각해야 한다(인쇄 252 / PDF 282). 스킬의 적용 지침: 변경마다 어느 모델의 어떤 경험을 개선하는지 설명할 수 있어야 한다.

## 핵심 개념

- **수치 모듈화**: 독립 설계·집중 관리가 가능한 수치 구조의 분류 방식(인쇄 239 / PDF 269).
- **속성 분배 모델 조합**: 표준 속성 성장을 각 성장 모듈에 비율로 배분하는 조합(인쇄 242 / PDF 272).
- **육성 가성비**: 성장 수익을 소비로 나눠 얻는 모듈별 실제 육성 경험의 판단값(인쇄 242–243 / PDF 272–273).
- **고정 생산 / 랜덤 생산 모델**: 고정 보상 플레이와 드롭·패키지 같은 확률 보상 플레이를 구분하는 생산 모델(인쇄 243 / PDF 273).
- **경제 검증 모델**: 생산·소비·자원 잔여를 주기 단위로 집계해 압박과 동력을 예측하는 모델(인쇄 243 / PDF 273).

## 핵심 요약

1. 모듈은 독립적으로 설계하되 게임 경험은 모델 간 연결로 검증한다.
2. 10단계의 번호는 설계 편의를 위한 기본 순서다. 모델 4는 모델 8의 성장 검증 데이터로 다시 보정하고, 모델 10은 필요할 때 구축해 검증에 쓰므로 일방향 의존 순서로 고정하지 않는다.
3. 시스템 하나를 매개변수 정의, 데이터 호출, 모델 계산의 세 단계로 나누면 입력과 결과를 추적할 수 있다. 원문은 이 세 단계를 성유물 한 시스템으로 시연한다(인쇄 245–250 / PDF 275–280). 스킬의 적용 지침: 다른 시스템에도 같은 세 단계를 쓸 수 있다.

## 연결

- **1장**: 원문은 1장의 수치 프로세스 5단계를 각각 하나의 수치 모듈로 보고, 모듈이 크고 작은 수치 모델로 구성된다고 한다(인쇄 239 / PDF 269). 전투 모듈은 속성·전투 프로세스·공식·성장·분배·육성 기능·몬스터 난이도 모델 등으로 구성된다(인쇄 239 / PDF 269).
- **3~6장**: 전투·경제·검증·수익화 모델은 10단계의 상세 구현이다.
- **7장**: 원문은 각 기능의 수치 요구 사항을 프로세스화해 처리하는 데 수치 시각화가 가장 편리한 방법이라고 한다(인쇄 251 / PDF 281). 스킬 정리: 수치 시각화는 모듈별 경험과 연결 이상을 찾아내는 출발점이다.
