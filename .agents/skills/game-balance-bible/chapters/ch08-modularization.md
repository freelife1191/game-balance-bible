# 8장: 수치 모듈화

## 핵심 아이디어

**수치 모듈화**는 게임의 기능·플레이·성장을 이루는 수치 구조를 독립적으로 설계하고 집중 관리하는 방식이다. 핵심은 모든 수치를 **수치 모델**로 만드는 데 있다. 모델은 독립성을 가져야 하지만, 실제 게임 경험은 모델 간 연결에서 생기므로 통합성도 보존해야 한다. 좋은 최적화는 전체 숫자를 한꺼번에 흔들거나 한 칸만 고치는 일이 아니라, 경험이 나쁜 수치 모델을 찾아 연결 영향을 확인하며 조정하는 일이다.

## 수치 모델의 범위와 계약

수치 모델은 변수, 등식, 부등식, 수학적 연산, 언어 규칙으로 대상의 특징과 내부 연결성을 설명한다.

- **넓은 의미의 수치 모델**: 특정 콘텐츠의 모델 집합. 예: 전투 기본 모델, 성장 모듈 육성 모델, 몬스터 난이도 모델을 아우르는 전투 모델.
- **좁은 의미의 수치 모델**: 독립된 한 모델. 예: 전체 생산 모델, 드롭 모델.
- **독립성**: 모델별 콘텐츠·매개변수·계산 책임이 분리되어 있는 성질.
- **통합성**: 속성 정의가 성장 모델의 기반이 되고, 공식이 속성의 척도가 되는 것처럼 모델들이 하나의 경험을 만드는 성질.

각 모델에는 외부 특성인 **기능·상태·인터페이스**와 내부 특성인 **로직**을 명시한다. 이것이 모듈 간 전달 데이터와 변경 영향의 경계를 만든다.

가장 단순한 성장 모델도 명시적으로 쓴다.

`공격력 = 초깃값 매개변수 + (레벨 - 1) × 레벨 증폭 매개변수`

예를 들어 초깃값 100, 레벨 증폭 50이면 레벨 10의 공격력은 550이다. 초깃값과 증폭값은 상수, 레벨은 독립변수다. 단순한 식이라도 어떤 입력이 어떤 결과를 바꾸는지 추적할 수 있어야 한다.

원문 표 8.1(인쇄 240쪽)은 이 예시의 입력을 `초깃값 매개변수 100`, `레벨 증폭 매개변수 50`으로 분리해 적는다. 표 8.2는 같은 식의 결과를 레벨 1·10·50·100에서 각각 `100 / 550 / 2,550 / 5,050`으로 검산한다. 즉, 이 두 표의 역할은 복잡한 성장 곡선을 권장하는 것이 아니라 **매개변수 표와 산출값 표를 분리해 한 식의 입력·출력을 추적**하게 하는 것이다.

## 핵심 프레임워크: 수치 모델 10단계

| 단계 | 모델 | 소속 | 핵심 산출물·검증 |
|---|---|---|---|
| 1 | 기초 성장 모델 | 전투 | 레벨 성장 등 게임 생명주기·리듬·경험 주기의 기초 |
| 2 | 속성 성장 모델 | 전투 | 직업별 표준 속성 성장 경험, 전투 기본 모델로 1차 밸런스 |
| 3 | 성장 모듈 성장 모델 | 전투 | 속성 분배 모델 조합으로 각 육성 모듈에 1단계 속성을 배분 |
| 4 | 몬스터 난이도 모델 | 전투 | 유저 성장에 대응하는 적 데이터셋; 성장 검증 후 재보정 |
| 5 | 성장 소비 모델 | 경제 | 성장 모듈과 1:1 대응하는 비용과 육성 가성비 |
| 6 | 생산 모델 | 경제 | 모든 플레이의 생산량; 고정 생산/랜덤 생산 구분 |
| 7 | 경제 검증 모델 | 검증 | 생산 검증·소비 검증·주기별 자원 잔여량 |
| 8 | 성장 검증 모델 | 검증 | 각 주기의 실제 성장 데이터와 몬스터 난이도 근거 |
| 9 | 수익화 검증 모델 | 수익화 | 수익화 전략 집계와 주기별 수익 예측 |
| 10 | 전투 기본 모델 | 전투 | 직업 밸런스와 단계별 몬스터 난이도 검증 |

### 의존 순서와 피드백 루프

원문 그림 8.1(인쇄 241쪽)은 네 상위 분류(전투·경제·검증·수익화)와 10개 모델을 한 선형 파이프라인이 아니라 **연결망**으로 그린다. 1→2 뒤에는 `속성 분배 모델 조합`이 A/B/C 성장 모듈(3)로 나뉘고, `생산 분배 모델 조합`은 생산 모델(6)로 향한다. 7은 생산 집계를 받아 `생산 검증 → 소비 검증`을 수행하고, 그 결과의 `자원 잔여 비율`은 충전 검증·소비 검증(그림의 9)에 연결된다. 8은 `레벨 검증 → 육성 검증`을 거쳐 4의 몬스터 난이도를 보정하고, 2와 4의 결과는 10 전투 기본 모델에서 각각 첫 번째·두 번째 밸런스 확인으로 합류한다.

텍스트로 읽는 기본 순서는 1→2→3으로 유저 성장의 기준과 분배를 정하고, 4는 그 성장의 피드백으로 적 난이도를 만든다. 5의 소비는 3의 성장 수익과 1:1로 대응하며, 6은 그 소비를 충족할 플레이 생산을 설정한다. 7은 `생산 - 소비 = 주기별 자원 잔여`로 경제 압박과 성장 원동력을 본다. 8의 실제 성장 데이터는 4의 몬스터 난이도를 보정한다. 9는 수익화 전략을 집계·계산해 주기별 수익을 예측한다.

순서는 설계 편의를 위한 기본값이다. 특히 4는 초기에는 추정 성장 데이터로 시작하고, 8이 완성되면 실제 검증 데이터로 갱신한다. **10 전투 기본 모델은 반드시 마지막에 새로 만드는 단계가 아니라 필요할 때 구축하는 검증 모델**이며, 원문은 기본 속성 성장과 성장 검증을 이 모델로 반드시 검증하라고 한다.

## 수치 모델 구축의 3단계

저자의 구축 방법은 **아이디어 구상 → 세부 사항 보강 → 모델링**을 다음 세 작업으로 실현한다.

1. **매개변수 정의** — 기능의 세부 규칙과 설계 의도를 먼저 문장·표로 고정한다. 선택지, 상한, 희귀도, 슬롯, 확률, 성장 횟수처럼 결과에 직접 영향을 주는 변수를 빠뜨리지 않는다.
2. **데이터 호출** — 다른 모델이 이미 계산한 기준 수치를 참조한다. 독립 모델이라고 임의 기준을 새로 만들지 않는다. 예를 들어 한 성장 모듈의 속성 총량은 `속성 성장 데이터 × 모듈의 속성 비율`로 가져온다.
3. **모델 계산** — 정의한 매개변수와 호출 데이터를 식·표에 넣어 초기값, 성장값, 확률 풀, 비용과 보상을 계산한다. 결과는 다음 모델이 사용할 수 있는 표로 고정한다.

### 원문 성유물 예시: 재현 가능한 입력과 계산

아래는 원문이 `<원신>` 성유물로 설명한 **책의 설계 예시**(인쇄 244~249쪽)다. 현재 게임의 실제 규칙·확률·수치라고 가정하지 않는다. 예시의 목적은 무작위 성장 모듈을 `규칙 → 입력 표 → 호출 데이터 → 산식 → 결과 표`로 완결하는 방법을 보이는 데 있다.

#### 1. 규칙과 풀의 스키마

- 장착 부위는 5개다. 주 속성과 부속성은 같은 속성이 중복되지 않으며, 주 속성은 최대 1개·부속성은 최대 4개다.
- 1·2부위의 주 속성은 각각 공격력·HP로 고정하고, 3~5부위는 정해진 주 속성 풀에서 하나를 고른다. 원문 표 8.3의 주 속성 출현 횟수는 `공격력 1, 방어력 0, HP 1, 공격력% 3, 방어력% 3, HP% 3, 원소 마스터리 3, 원소 충전 효율 1, 원소 피해 보너스 1, 물리 피해 보너스 1, 치명타 확률 1, 치명타 피해 1, 치유 보너스 1`이다.
- 부속성 풀은 부위·주 속성에 따라 제외 항목이 생긴다. 원문 표 8.4의 **출현 횟수**는 공격력 4, 방어력 5, HP 4, 공격력% 4, 방어력% 4, HP% 4, 원소 마스터리 4, 원소 충전 효율 4, 원소 피해/물리 피해 보너스 0, 치명타 확률 4, 치명타 피해 4, 치유 보너스 4다. 이는 주 속성과 같은 항목을 부속성에서 다시 뽑지 않는 규칙을 반영한 집계다.
- 별 등급은 1~5성이고 승급하지 않는다. 원문 예시의 주 속성 비율은 `60/70/80/90/100%`, 부속성 비율은 `20/40/60/80/100%`다. 최대 레벨은 `별 등급 × 4`, 5성 초기 속성 비율은 15%, 돌파 가능 횟수는 5회다.
- 4레벨마다 속성이 4개 미만이면 부속성 1개를 반드시 추가한다. 이미 4개면 4개 중 하나를 무작위 강화한다. 원문은 연속 강화가 “꽤 높은 확률”로 일어날 수 있다고만 하며, **선택 확률이나 가중치는 제시하지 않는다**. 따라서 독립 균등 추첨 확률을 이 예시에 덧붙이면 안 된다.
- 부속성 변동 구간은 70%, 80%, 90%, 100% 네 단계다. 구간 간격을 넓히면 원하는 완벽 속성이 나올 확률이 낮아지고, 좁히면 육성 경험이 완만해진다는 것이 원문의 설계 판단이다.

#### 2. 호출 데이터와 대표 검산

원문 표 8.8은 다른 성장 모델에서 호출한 5성 기준 총속성 중 주 속성 공격력 311, 부속성 공격력 388을 쓴다. 주 속성 초기값은 다음처럼 계산한다.

`초기 속성 = 5성 초기 비율 × 별 등급 주 속성 비율 × 속성 총합 ÷ 속성 출현 횟수`

따라서 5성 1부위 공격력은 `15% × 100% × 311 ÷ 1 = 46.65`, 원문은 이를 반올림해 47 pt로 제시한다. 부속성 풀의 최댓값은 다음과 같다.

`부속성 최댓값 = (별 등급 부속성 비율 × 속성 총합) ÷ (속성 출현 횟수 × 돌파 가능 횟수)`

5성 공격력 부속성의 경우 `(100% × 388) ÷ (4 × 5) = 19.4`이며, 원문 표는 반올림한 19 pt를 싣는다. 실제 한 번의 부속성 값은 이 최댓값에 70/80/90/100% 변동 구간을 적용해 구성한다. 적용 후 반올림 규칙은 원문이 명시하지 않으므로 프로젝트 구현에서 별도로 고정해야 한다.

#### 3. 레벨 표를 재현할 때의 주의

원문 표 8.10은 5성에서 초기 15%, 레벨 1의 19.25%, 레벨 15의 78.75%, 레벨 20의 100.00%를 제시한다. 표의 5성 열은 `15% + ((1 - 15%) ÷ 20 × 현재 레벨 × 100%)`로 재현된다. 이 식은 **표의 누적 속성 비율을 재현한 식**이다. 원문에 인쇄된 ‘레벨당 업그레이드 비율’ 표기는 초기 비율을 더하는 표현을 생략하므로, 구현에서는 `초기값`, `레벨당 증가분`, `표시 누적값`을 분리해 검산한다. 예컨대 표의 5성·15레벨 공격력은 `78.75% × 311 = 244.9125`이며 원문은 245로 제시한다.

이 예시의 산식은 입력 표의 출현 횟수·별 등급 비율·돌파 횟수에 의존한다. 어느 하나를 바꾸면 초기 주 속성, 부속성 풀, 레벨 표를 함께 다시 계산해야 한다.

## 왜 작동하는가 / 실패 모드

- **왜 작동하는가**: 문제 경험을 특정 모델로 포지셔닝하고, 입력·출력·연결을 보며 전체를 무너뜨리지 않고 조정할 수 있다.
- **실패: 모든 숫자를 한 번에 조정** — 원인을 찾지 못하고 회귀를 키운다. 사용자 경험이 나쁜 모델을 먼저 특정한다.
- **실패: 독립성을 고립으로 오해** — 소비 모델의 비용을 바꿔 놓고 생산·성장·수익화를 재검증하지 않으면 통합성이 깨진다.
- **실패: 감각으로만 수치 결정** — 수치 시스템은 여러 모델의 계산 결과다. 가설도 변수·등식·표로 표현해 검증 가능하게 만든다.
- **실패: 모듈을 재사용하지 않음** — 요구사항마다 새 표를 만들면 속도만 빨라지고 수치 경험은 축적되지 않는다. 유사한 시스템은 모델의 계약과 검증 절차를 계승한다.

## 모듈화의 운영 원칙

수치 모듈화는 버전 업데이트에 따라 늘어나는 수치를 표준 모델로 흡수해 빠르게 대응하게 한다. 과거 게임의 우수한 모듈을 복각해 학습하는 것도 가능하지만, 숫자를 그대로 옮기는 것이 목적은 아니다. 어떤 경험을 만들었는지와 그 모델의 인터페이스·제약·검증 순서를 이해해 다음 프로젝트의 조건에 맞게 재사용한다.

원문 그림 8.2(인쇄 250쪽)는 중국 게임 산업의 PC 게임(2002~2009)·PC 웹 게임(2009~2013)·모바일 게임(2013~2020)·멀티 플랫폼(2020+) 시대를 `수작업 계산(2002~2010) → 조립 라인 방식(2010~2015) → 플랫폼 생산(2015~2018) → 모듈화 생산(2018+) → AI 시대(2025+)`와 나란히 둔 **저자의 발전 관점**이다. 이는 모듈화를 반복 가능한 생산 방식에 비유하는 맥락 자료이며, 현행 산업 분류·미래 예측·AI 도입의 근거로 사용하지 않는다.

수치 기획자에게 필요한 최종 역량은 방법을 암기하는 일이 아니라 **아이디어와 검증**이다. 시각화와 수치 검증으로 출시 전에 밸런스와 안정성을 확인하고, 변경마다 어느 모델의 어떤 경험을 개선하는지 설명할 수 있어야 한다.

## 핵심 개념

- **수치 모듈화**: 독립 설계·집중 관리가 가능한 수치 구조의 분류 방식.
- **속성 분배 모델 조합**: 표준 속성 성장을 각 성장 모듈에 비율로 배분하는 조합.
- **육성 가성비**: 성장 수익을 소비로 나눠 얻는 모듈별 실제 육성 경험의 판단값.
- **고정 생산/랜덤 생산 모델**: 고정 보상 플레이와 드롭·패키지 같은 확률 보상 플레이를 구분하는 생산 모델.
- **경제 검증 모델**: 생산·소비·자원 잔여를 주기 단위로 집계해 압박과 동력을 예측하는 모델.

## 핵심 요약

1. 모듈은 독립적으로 설계하되 게임 경험은 모델 간 연결로 검증한다.
2. 10단계는 성장 기준 → 분배·난이도 → 소비·생산 → 검증·수익화 → 전투 검증의 의존 순서를 드러낸다.
3. 모든 시스템은 매개변수 정의, 데이터 호출, 모델 계산의 세 단계로 추적 가능하게 만든다.

## 연결

- **1장**: 수치 프로세스 5단계가 상위 수치 모듈이 된다.
- **3~6장**: 전투·경제·검증·수익화 모델은 10단계의 상세 구현이다.
- **7장**: 수치 시각화는 모듈별 경험과 연결 이상을 찾아내는 출발점이다.
