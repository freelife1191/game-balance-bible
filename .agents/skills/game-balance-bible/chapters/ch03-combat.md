# 3장: 게임의 전투 수치

> 표기: `(인쇄 N / PDF M)`이 붙은 문장은 책의 서술이다. ‘스킬 정리’·‘스킬의 적용 지침’ 표시와 **실무 절차**, **왜 작동하는가**, 판단 도구·안티패턴·압축 재구성 예시·핵심 요약은 이 스킬이 책을 바탕으로 정리한 것이며, 그 안에서도 위치가 붙은 문장은 책의 서술이다.

## 핵심 아이디어

전투 수치는 단순히 공격력과 체력을 정하는 일이 아니다. 저자는 이를 **속성 정의 → 전투 구조 → 능력치 정량화 → 인공지능(AI)**의 네 단계로 전개한다(인쇄 26 / PDF 54). 스킬 정리: 먼저 무엇을 계산할지 정하고, 그 값을 언제 어떤 순서로 계산할지 고정한다. 그다음 성장·직업·NPC에 같은 기준을 적용하고 실제 전투로 다시 검증해야 한다.

원문은 **캐릭터 생존 주기 = 체력 ÷ 대미지**로 정의한다(인쇄 58·91 / PDF 86·119). 스킬 정리: 이 장의 기준점은 이 생존 주기이며, 목표 생존 주기(턴 수)를 먼저 정하면 공격·방어·체력의 교환비, 몬스터 난이도, 직업의 역할 수익을 하나의 전투 리듬으로 연결할 수 있다.

## 핵심 프레임워크

### 전투 수치 4단계

1. **속성 정의** — 전투에 필요한 입력값과 각 값의 포지션을 정한다.
2. **전투 구조** — 기초·스킬·대미지 플로 및 각 플로의 공식을 정한다.
3. **능력치 정량화** — 밸런스 기준을 성장 벤치마크와 육성 루트로 풀어낸다.
4. **인공지능** — 위의 플레이어 기준 데이터를 NPC, 난이도, 보정 규칙에 적용한다.

원문은 이 단계를 순서대로 전개하면 게임의 완전한 전투 수치를 얻는다고 한다(인쇄 26 / PDF 54). 스킬 정리: 순서를 바꾸면 후단의 성장·NPC 수치를 계산할 공통 기준이 없어진다. 신규 콘텐츠는 먼저 기존 공식과 리듬을 통과하는지 확인하고, 특수 규칙은 그다음에 추가한다.

### 속성 정의: 단계적 분류와 효용 분류

- **단계적 분류**: 1단계는 전투에 직접 작용하는 공격·방어·체력, 2단계는 명중/회피·치명 공격/치명 저항·패링처럼 1단계 위에 만들어지는 확률 속성, 3단계는 이들을 수정하는 속성이다. 2단계 속성의 가장 큰 특징은 **무작위성**이다(인쇄 27–29 / PDF 55–57). 원문 표기: 본문은 2단계를 단일 대미지 계산에 직접 영향을 주는 백분율 속성으로 쓰지만(인쇄 29 / PDF 57), 그림 3.2는 2단계에 ‘전투에 간접 영향’이라고 적어 원문 안에서 엇갈린다(인쇄 28 / PDF 56). 표 3.1은 명중·회피·치명 공격을 2단계 수치로, 명중률·방어 관통·치명 공격 확률을 3단계 백분율로 따로 둔다(인쇄 32 / PDF 60). 3단계 속성은 게임 설계 초반에 설정해 두지 않아도 된다(인쇄 29 / PDF 57).
- **효용 분류**: 공격·방어·체력이라는 전투 과정을 중심으로 속성을 분해한다. 예를 들어 공격력→물리/마법 공격→명중·치명·관통으로 확장한다.
- **일반 속성**은 장르를 가리지 않고 쓰이는 공격·방어·체력 등의 속성이다. **비일반 속성**은 특정 장르의 게임에만 쓰인다. 게임에는 일반 속성이 반드시 있어야 하지만 비일반 속성은 꼭 필요하지 않다(인쇄 26 / PDF 54). 비일반 속성은 기초 속성(예: 힘·민첩·지능)과 특수 속성(예: 이동 속도·공격 속도)으로 나뉘며, 3대 또는 5대 기초 속성이 자주 쓰인다(인쇄 33 / PDF 61).
- 원문은 속성을 정의할 때 확실하지 않으면 가장 간단한 방법을 고르라고 한다. 같은 장르 게임의 속성을 빌려 오고 고유한 속성을 더해 기초 인프라 모듈을 완성하라는 뜻이다(인쇄 34 / PDF 62). 속성의 종류와 수는 제작 중에 바꿀 수 있다(인쇄 34 / PDF 62). 특수 속성은 적절히 쓰면 게임 경험을 크게 높이지만 지나치면 전투력 밸런스가 무너질 수 있다(인쇄 33 / PDF 61). 속성 분류는 정의를 쉽게 하려는 것이므로 유저에게 보여 주는 실제 속성일 필요가 없다(인쇄 27 / PDF 55).

**언제 쓸까:** 원문은 두 분류 모두 목표에서 거꾸로 내용을 채우는 결과 지향적 방식이며, 어느 쪽을 고를지는 개인 취향의 문제이고 실제 효과는 큰 차이가 없다고 한다(인쇄 27 / PDF 55). 단계적 분류는 접근성이 좋고 속성 효과를 깔끔하게 정리하기 좋으며(인쇄 27 / PDF 55), 효용 분류는 더 구체적이고 실전 경험에 충실하다(인쇄 30 / PDF 58). 스킬 정리: 팀 문서와 구현 구조를 맞추려면 단계적 분류, 한 번의 공격에 필요한 효과를 빠르게 찾으려면 효용 분류가 편하며, 한 프로젝트 안에서는 하나를 표기 체계로 정해 두면 혼동이 줄어든다.

**왜 작동하는가:** 원문은 공격의 종류가 많을수록 상응하는 방어의 종류도 많아지고 밸런스 설계가 복잡해진다고 한다. 유저의 입문 난이도와 캐릭터의 성장 난이도도 비례해 올라간다고 한다(인쇄 28 / PDF 56). 스킬 정리: 따라서 공격/방어의 종류는 게임 장르와 테마가 요구하는 만큼만 둔다. 저자는 일반적인 상황에서 1~3종이면 충분하다고 본다(인쇄 28–29 / PDF 56–57).

### 전투 플로: 기초·스킬·대미지

- **기초 플로**: 전투 진입 → 데이터 초기화 → 패시브 스킬 수행 → 턴 순환이다(인쇄 36–37 / PDF 64–65). 원문 도식에서는 각 턴의 시작에 전투 종료를 먼저 판정하고, 계속이면 전투 플로 → 스킬 플로 → 대미지 플로를 실행한 뒤 다시 종료 판정으로 돌아간다. 종료일 때만 전투 결과로 돌아가 전투 이탈을 한다(인쇄 36 / PDF 64). 실시간 전투도 공격 간격과 속도로 빈도를 정의한 턴의 연속으로 모델링할 수 있다(인쇄 35 / PDF 63). 턴제는 속도 등으로 선제공격이 정해지므로, 양쪽 속성이 같으면 선제공격한 쪽이 한 번 더 공격해 우위를 점한다(인쇄 35 / PDF 63).
- **스킬 플로**: 스킬 시전 → 대상 선택·순회 → 명중 판정 → 명중 시 시전자 버프와 대상 디버프 발생 → 버프 기록 → 다음 대상 또는 종료다. 대상이 없으면 반격/패링 같은 처리로, 전체 스킬이 끝나면 턴 후 스킬·버프 효과·버프 제거로 이어진다(인쇄 38 / PDF 66). 본문은 대미지 연산 단계에서 대상이 죽었는지 판단해 죽었으면 기초 플로로 돌아가고, 살았으면 버프 부여로 진행한다고 쓰지만 그림 3.6에는 이 분기가 없다(인쇄 38 / PDF 66). 대상은 단일 개체나 집단일 수 있고, 대상 수에 따라 최종 대미지를 약간 수정해야 한다(인쇄 38 / PDF 66). 원문은 패시브 스킬을 기초 플로의 ‘전투 진입’ 단계에서 통합해 연산하고, 스킬 플로는 주로 액티브 스킬의 시전 플로를 말한다고 한다(인쇄 37 / PDF 65). 스킬 플로의 대미지 부분은 대미지 플로의 연산을 직접 호출하고, 버프는 기초 플로에 병합해 처리한다(인쇄 37 / PDF 65). 원문은 스킬 플로를 수치 측면에서 대미지(기본 대미지를 늘리는 백분율 또는 고정값)와 버프(대상에게 지속 시간이 있는 상태를 부여하며 정방향·역방향이 있음)로 구성한다(인쇄 37 / PDF 65). 스킬 플로가 완전히 버프에 기반하는 게임의 예로, 원문은 스킬 대미지가 공격력의 130%이면 시전할 때 먼저 한 턴 동안 공격력 +30% 버프를 주고 대상 쪽에서는 스킬 대미지 증가를 다시 대입하지 않는 방식을 든다(인쇄 39 / PDF 67). 스킬의 적용 지침: 도식의 명중 뒤 버프는 대표 구조이므로, 대미지·사망 판정이 어느 모듈에 귀속되는지와 재진입 조건을 명세에서 고정한다.
- **대미지 플로**: 원문 그림 3.7은 대미지 생성 → 회피 판단(예이면 바로 결과로) → 치명 공격 판단 → 저항 판단 → 대미지 계산 → 대상 출혈 → 흡혈 판단(예이면 행위자 스킬 플로로) → 대상 사망 판단(예이면 행위자의 처치 버프 발생) → 결과로 돌아가기 순서다(인쇄 40 / PDF 68). 치명이 발생하면 저항 판단을 거치지 않고 치명 공격 대미지로, 저항이 발생하면 저항 효과로 대미지 계산에 합류한다(인쇄 40 / PDF 68). 스킬 정리: 도식의 ‘대상 출혈’은 계산된 피해가 대상 체력에서 빠지는 단계로 읽히며 출혈 디버프와 다르고, 흡혈·사망 판단은 이 계산 결과에 의존한다. 원문은 대미지 플로를 확률론 알고리즘과 원탁 이론 알고리즘의 두 유형으로 나누고, 관통을 포함한 2단계 속성의 판정 우선순위를 각 알고리즘에서 정한다(인쇄 40–41 / PDF 68–69).

원문은 액션 요소가 있는 게임이면 수치 기획자가 매 공격 사이의 시간과 공격 후 경직 시간을 이해해야 한다고 하며, 공격·스킬 모션이 공격 전·후 경직을 만든다고 설명한다(인쇄 25 / PDF 53). 스킬 정리: 이 시간은 실제 행동 빈도에도 들어가므로 공격 속도 표만으로 처치 시간을 확정하지 말고 애니메이션·경직·스킬 플로가 실제 타격 간격에 미치는 영향을 함께 본다.

**실무 절차:** 각 상태에 입력·출력·지속 범위·재진입 조건을 적고, 난수 판정의 우선순위와 동시 발생 가능성을 정의한다. ‘최종 대미지 130%’와 ‘공격력 +30% 후 기본식 호출’은 비선형 피해식에서 동등하지 않다. 같은 보너스 출처의 이중 적용을 피하되, 독립된 속성 버프와 최종 배율은 적용 순서를 정해 함께 사용할 수 있다. [계산 예시](../references/combat-formulas.md)를 확인한다.

### 확률론 알고리즘과 원탁 이론 알고리즘

- **확률론 알고리즘**: 우선순위대로 독립 판정을 이어서 한 공격 결과를 선택한다. 예를 들어 명중 70%, 관통 30%, 치명 5%이고 순서가 명중→관통→치명이라면 실제 관통은 `0.70×0.30=21%`, 실제 치명은 `(0.70-0.21)×0.05=2.45%`, 일반 공격은 `46.55%`다(인쇄 41 / PDF 69). 낮은 우선순위의 표시 확률은 실제 수익이 아니다.
- **원탁 이론 알고리즘**: 결과 칸들이 총 100%의 원탁을 나눠 가진다. 합이 100% 이하이면 각 표시 확률을 그대로 보존하지만, 높은 우선순위의 합이 100%에 닿으면 낮은 결과는 원탁에서 밀려난다(인쇄 41–42 / PDF 69–70).

**판단 규칙:** 원문은 어느 알고리즘이 맞고 틀린 것이 아니라 각자 장단점이 있으므로, 장단점과 2단계 속성에 미치는 영향을 이해하고 자기 게임에 맞는 방식을 고르라고 한다(인쇄 40·42 / PDF 68·70). 확률론은 모든 속성이 대미지 계산에 들어가고 2단계 속성의 범위를 넓힐 수 있으며, 아이템 결제가 가능한 게임에서 자주 쓰인다(인쇄 41 / PDF 69). 원탁은 속성 범위 요구가 더 엄격하다(인쇄 42 / PDF 70). 스킬의 적용 지침: 속성의 조합·성장 폭을 크게 만들고 저우선 속성의 기댓값 하락을 보정할 수 있으면 확률론을 쓴다. 표시 확률과 실제 발생률의 일치를 중시하면 원탁을 쓰되, 모든 구간에서 누적 우선순위 합과 ‘탈락한 결과’를 검증한다. 두 방식을 섞을 때는 동일 플로 안에서 판정 의미가 충돌하지 않게 한다.

### 공식 정의와 수익 곡선

속성 계산 공식은 모든 육성 루트의 고정값을 합친 뒤 백분율을 적용하는 방식으로 시작한다(인쇄 43 / PDF 71). 원문 예시로, 백분율이 **대공식**(최종 결과식)에 있으면 속성 10%가 최종 공격력 10%로 이어질 수 있고, **소공식**에 있으면 100%를 올려도 최종 공격력이 5%만 오를 수 있다(인쇄 43 / PDF 71). 원문은 초기 설정 단계에서는 육성 루트를 완벽히 계획할 수 없으므로 캐릭터·장비 같은 큰 범주로 정의하되, 향후 추가할 수 있는 육성 루트를 구조에 미리 넣어 둘 수도 있다고 한다(인쇄 43 / PDF 71). 힘·지혜·정신력 같은 기초 속성이나 3단계 속성은 대부분 전투 플로에 직접 들어가지 않으므로 속성 변환 공식으로 다른 속성에 연결하며, 저자가 삼국지 테마 게임에서 이런 속성을 일부러 대미지 매개변수에 넣은 예외도 있다(인쇄 44 / PDF 72).

저자는 기본 뺄셈, 업그레이드 뺄셈, 곱셈, 나눗셈 대미지 공식을 비교한다. 정확한 식과 변수 단위는 [combat-formulas.md](../references/combat-formulas.md)를 참조한다.

- 기본 뺄셈은 방어가 공격 이상이면 무적 상태가 될 수 있다(인쇄 50 / PDF 78). 속성 격차가 커질수록 대미지 수익이 비례해 커지는 한계효용체증을 보여 과금 유저의 공격 수익이 빠르게 늘고(인쇄 53 / PDF 81), 방어 1pt마다 실제 가치가 있어 방어를 올리려는 동기가 가장 강하다(인쇄 55 / PDF 83).
- 업그레이드 뺄셈과 곱셈은 수치 안정성·결함 허용성이 높고(인쇄 53–54 / PDF 81–82), 방어 변환 상수로 한계효용체감을 만든다(인쇄 55–56 / PDF 83–84). 방어 속성의 임곗값은 대미지 공식의 상수로 정해지며, 상수가 클수록 임곗값도 커진다(인쇄 56 / PDF 84). 원문은 버전이 바뀌며 속성을 계속 추가해야 한다면 공격력과 체력을 직접 설정해 전투 리듬을 안정시키라고 한다(인쇄 56 / PDF 84).
- 나눗셈은 공격 수익이 크게 증폭되어 핵 앤 슬래시식 성장에는 쓸 수 있으나, PvP의 생존 주기를 불안정하게 만들 수 있다(인쇄 51 / PDF 79). 원문 표기 / 문맥: 인쇄 51쪽의 핵 앤 슬래시 장점 문장은 ‘곱셈 공식’으로 적혀 있으나 나눗셈 공식 문단 안의 서술이고, 공식 선택 지침도 핵 앤 슬래시에 나눗셈을 든다(인쇄 56 / PDF 84).

저자의 판단으로 수치 안정성·유저 경험·결함 허용성은 업그레이드 뺄셈 = 곱셈 > 뺄셈 > 나눗셈, 대미지 수익과 수치 설계 난이도는 나눗셈 > 뺄셈 > 업그레이드 뺄셈 = 곱셈 순이다(인쇄 53–54 / PDF 81–82). 방어 수익은 뺄셈이 가장 높고 나머지 셋은 같으며(인쇄 55 / PDF 83), 유저의 방어 속성 이해도는 뺄셈 > 업그레이드 뺄셈 > 곱셈 > 나눗셈 순이다(인쇄 56 / PDF 84).

**공식 선택 지침:** 원문은 도전 난이도가 있어 방어 속성이 중요한 게임은 뺄셈, 공격 속성이 중요한 핵 앤 슬래시는 나눗셈, 유저 상호작용이 중요한 RPG는 업그레이드 뺄셈이나 곱셈을 쓸 수 있고, 결정하기 어려우면 업그레이드 뺄셈을 추천한다(인쇄 56 / PDF 84). 한 게임에서 공식을 섞을 수도 있으며, 원문 사례인 <Asktao>는 물리 대미지에 뺄셈, 마법 대미지에 곱셈을 쓴다(인쇄 56 / PDF 84). 원문은 절대적으로 좋은 공식은 없으며, 공식을 고른 뒤 대량의 데이터로 대미지 수익과 방어 수익을 연구하라고 한다(인쇄 56 / PDF 84). 원문 예시 상수는 [대미지 모델](../references/combat-formulas.md#대미지-모델)에 모았다.

**실무 절차:** 공식을 고르기 전에 저·중·고성장, 라이트/헤비 유저, 동레벨/레벨 차이 조합을 대입한다. 각 구간의 최종 피해, 피해 감소율, 생존 주기를 그래프로 확인한 뒤 상수와 캡을 결정한다. ‘피해 감소율이 높다’와 ‘방어 1pt의 한계 가치가 높다’를 혼동하지 않는다.

생존 주기의 `HP/피해`는 피해 단위에 따라 타격·턴·초가 달라지는 근사다. 고정 피해의 타격 횟수는 올림하며, 정확한 초 단위 시간은 공격 간격과 첫 타격 시점까지 정한다. 원시 피해가 음수면 실제 피해 하한부터 정하고, 실제 피해가 0이면 0이나 음수로 나누는 식으로 생존 주기를 만들지 않는다. 상세 조건은 [전투 공식](../references/combat-formulas.md)을 읽는다.

### 능력치 정량화와 밸런스

**능력치 정량화**는 육성 시스템을 만드는 일이며, **성장 구축 → 성장 분할 → 성장 세분화**로 이루어진다. 성장 구축은 시간과 연결된 레벨 같은 **성장 벤치마크**를 고르고 전체 속성 성장 곡선을 정한다. 성장 분할은 총 속성 중 각 육성 루트의 몫을 정하며, 성장 세분화는 루트마다 다른 업그레이드 횟수와 1회 속성 증가량을 정한다(인쇄 57 / PDF 85).

- **하위 밸런스 / 가치 밸런스**: 원문은 전투력 밸런스를 설계할 때 공식 정의의 밸런스인 하위 밸런스를 먼저 풀고, 전투 플로의 밸런스인 상위 밸런스를 그다음에 마무리하라고 한다(인쇄 58 / PDF 86). 목표 생존 주기를 정하고 최소수 추론으로 공격·방어·체력의 등가 가치를 구한다. 원문은 비교적 흔한 생존 주기를 6~20턴으로 보고 이 범위에서 하나를 고르되 나중에 조정할 수 있다고 한다(인쇄 58 / PDF 86). 기본 뺄셈이면 10턴에서 피해 1·체력 10, 공격 2·방어 1이 되어 2:1:10이다(인쇄 59 / PDF 87). 다른 공식은 방어가 변환 공식으로 정해지므로 먼저 방어를 0으로 두어 공격 1·체력 10을 얻는다. 이어 피해 감소율의 범위 구간(일반적으로 20%~85%)을 정하고 공격 1pt = 방어 1pt로 본다(인쇄 59 / PDF 87). 체력은 감소율 곡선의 한계효용 임곗값에서 대미지 = 공격력 × 80%를 대입해 구하고, 원문은 1:1:8을 얻는다(인쇄 59–60 / PDF 87–88). 원문의 이후 예시는 1:1:8(인쇄 63 / PDF 91)과 1:1:10(인쇄 70 / PDF 98)을 함께 쓴다. 원문은 이렇게 구한 1단계 속성 가치로 가장 밀접한 기초 속성의 가치도 계산하며, 예시값은 인내력 1pt = 체력 10pt = 힘 1pt = 공격력 1pt다(인쇄 60 / PDF 88). 원문은 기초 속성의 변환 대상이 1단계 속성만이 아닐 수 있어 이 값을 추정치로 두고 다음 밸런스 설계 단계에서 다시 계산한다(인쇄 60 / PDF 88). 스킬 정리: 두 비율은 공식과 가정에 따라 달라지는 원문 예시값이므로 어느 하나를 모든 공식의 기준으로 쓰지 않는다.
- **상위 밸런스**: 다수전은 일대일과 다른 문제다. 원문은 직업 차이로 생기는 경험 차이는 직업 밸런스 문제라 상위 밸런스에서 다루지 않고, 단일 유저가 여러 대상을 상대할 때의 밸런스를 다루며, 대상이 AI면 AI의 공격 강도를 조절해 맞출 수 있다고 한다(인쇄 60 / PDF 88). 책은 일대일 교전에 란체스터 선형 법칙, 다수 유닛 교전에 제곱 법칙을 참조하고, 상위 밸런스는 전투 시뮬레이션으로 맞추는 방법을 추천한다(인쇄 60–61 / PDF 88–89). 스킬의 적용 지침: 란체스터 법칙은 집중공격 가능 여부 등 모델 가정이 맞을 때만 간이 예측으로 쓴다. 여러 대상에게 동시에 공격받을 때 대미지를 줄이는 설정은 대다수 게임에 없고 단체전에 과도하게 관여할 필요도 없지만, 캐릭터 생존 주기가 심각하게 영향받고 그런 환경이 자주 나타나면 다중 대미지 감소 메커니즘을 고려해야 한다(인쇄 60 / PDF 88).
- **직업 삼대장**: 제어 삼대장은 모든 직업이 딜러이면서 상성 삼각관계를 이루고, 협력 삼대장은 탱커·힐러·딜러의 역할로 밸런스를 이룬다(인쇄 61 / PDF 89). 원문은 싱글 모험·개인 영웅주의에 초점을 둔 게임은 제어 삼대장을, 팀워크·사교·협력에 초점을 둔 게임은 협력 삼대장을 우선 선택하고(인쇄 61–62 / PDF 89–90), 제어 삼대장은 직업 간 가치 밸런스에, 협력 삼대장은 가치 밸런스와 역할 밸런스 모두에 주의하라고 한다(인쇄 62 / PDF 90).
  - 가치 밸런스는 탱커는 생존 주기, 딜러는 초당 피해(DPS), 힐러는 단위시간 치유 효과로 비교하며(인쇄 62 / PDF 90), 제어 삼대장은 딜러 대미지만, 협력 삼대장은 나머지 두 유형까지 맞춘다(인쇄 63 / PDF 91). 원문 예시는 표준 직업 1:1:8에서 체력 1pt = 전투력 1pt로 두어 공격·방어 1pt를 전투력 8pt로 환산하고, 딜러를 1.5:0.75:6으로 정해 전투력 24를 같게 맞춘다(인쇄 63 / PDF 91).
  - 원문은 역할 밸런스를 여러 시나리오와 응용 환경에서 각 직업의 포지션과 역할이 맞는 개념적 밸런스로 설명한다(인쇄 63–64 / PDF 91–92). 단일 시나리오에 국한하지 않고 모든 직업이 가치를 발휘할 곳이 있어야 하며, 블리자드가 <월드 오브 워크래프트> 직업 포럼에 발표한 직업 밸런스 설계 원칙 다섯 가지를 예로 든다(인쇄 64 / PDF 92).
  - 역할 밸런스는 수치 기획자가 주로 스킬로 맞추며, 강한 제어(빙결·기절)와 약한 제어(속박)는 버프 지속 시간으로, 출혈·점화·중독 같은 지속 피해 디버프는 지속 대미지와 지속 시간으로 차이를 둔다(인쇄 64 / PDF 92).

**성장 벤치마크와 레벨 성장:** 원문은 성장 벤치마크로 가능하면 현실 시간과 연관된 육성 루트를 고르고, 다른 육성 루트와 이후의 분할·세분화가 모두 이 기준을 따르게 한다(인쇄 66 / PDF 94).

- 레벨업 경험치는 경험치 함수를 먼저 정해 게임 시간을 도출하는 순방향 추론과, 레벨업 시간을 먼저 정해 필요 경험치를 구하는 역방향 추론으로 정할 수 있으며, 순방향은 시간이 예측과 다르면 고칠 내용이 많고 데이터 편향이 생길 수 있다(인쇄 67 / PDF 95). 원문 예시는 몬스터 표준 생존 주기 5, 공격 간격 1초에서 이론상 1분에 12마리를 잡고, 물약 구매·휴식 같은 효율 감소를 넣어 1분에 6마리, 시간당 360마리로 레벨과 시간의 관계를 계산한다(인쇄 67 / PDF 95). 역방향 추론의 예로 원문이 든 <월드 오브 워크래프트> 경험치 공식 하나는 `경험치(레벨당 소모) = 1레벨당 시간 × (기본 경험치 + 레벨 증가 보정값 × 캐릭터 레벨) + 보정값`이다(인쇄 67 / PDF 95). 원문은 1레벨당 시간을 중요한 변수로 보고, 20~30레벨에 걸리는 총 시간을 단위 1로 두어 각 레벨에 균등하게 나누는 방식으로 1레벨당 시간을 구한다(인쇄 68 / PDF 96).
- 단위 레벨업 시간을 정하기 전에 경험치 획득이 개방형(일일 획득 제한 없음)인지 폐쇄형(매일 고정량)인지 정해야 한다(인쇄 68 / PDF 96). 원문은 현재 폐쇄형이 주류이며 유저 간 레벨 차이를 줄이고, 과금 유저는 별도로 설계한다고 한다(인쇄 68 / PDF 96). 단위 레벨업 시간은 개방형이면 보통 시간 단위(0.01시간~몇십 시간), 폐쇄형이면 일 단위(0.001일~10일)로 둔다(인쇄 68 / PDF 96).
- 원문 예시값으로 40레벨 이후 하루 2레벨이면 40→41은 0.48일, 41→42는 0.52일로 정의한다(인쇄 68 / PDF 96). 첫날·첫 주·첫 달 레벨처럼 운영상 중요한 시점에 주의하며, 원문 예시는 만렙 50과 장비 10세트를 60일 플레이에 맞게 분배한다(인쇄 68–69 / PDF 96–97).
- 레벨 성장에 걸리는 시간은 게임의 수명이고, 레벨 성장 속도는 게임의 성장 리듬을 반영한다(인쇄 69 / PDF 97).

레벨업 경험치는 대부분 한계효용체감을 보이지만 속성 성장은 선형 추세로 두어 초기와 후기의 속성 1pt 가치를 같게 유지한다(인쇄 69–70 / PDF 97–98). 버전이 바뀌며 속성 가치를 낮춰야 할 때는 가치를 유지한 채 해당 속성을 할인하거나 가성비를 높이는 방식을 쓰며, 원문은 이를 경제 수치에서 다룬다(인쇄 69–70 / PDF 97–98). 원문은 속성 성장이 기하급수로 늘면 버전이 바뀌면서 속성의 실제 가치를 통제할 수 없게 되어 전투력 밸런스에 매우 치명적이라고 경고한다(인쇄 70 / PDF 98).

- 원문은 확률론 알고리즘을 쓰면 2단계 속성값의 범위가 더 커질 수 있고 우선순위가 낮은 속성일수록 범위가 더 클 수 있으며, 원탁 이론 알고리즘을 쓰면 2단계 속성의 수치 조정을 제한해야 한다고 한다(인쇄 71 / PDF 99). 원문 예시는 확률론 알고리즘을 쓴다고 가정해 2단계 속성이 100%까지 도달할 수 있어도 버전 업데이트 여지를 남기려고 100레벨에 50%만 설정한다(인쇄 71 / PDF 99).
- 원문은 1단계 속성을 같은 비율로 스케일업하는 방법(인쇄 70 / PDF 98) 외에, 3대 또는 5대 기초 속성의 자체 성장을 정한 뒤 속성 변환 공식으로 1단계 속성 성장을 구하는 방법도 든다(인쇄 71–72 / PDF 99–100). 원문 예시는 힘·지능·인내의 초깃값을 10pt로 두고 레벨마다 10pt씩 올려 100레벨에 각 1,000pt가 되며, 힘 1pt = 공격력 2pt, 지능 1pt = 방어력 2pt, 인내 1pt = 체력 20pt로 가정해 공격력 2,000pt, 방어력 2,000pt, 체력 20,000pt를 얻는다(인쇄 72 / PDF 100).
- 스킬 정리: 확률론에서는 저우선 확률의 실제 발생값이 표시값보다 작아지므로 확률 속성은 상한과 실제 기대 수익을 함께 설계한다. 1단계 비율을 고정해도 레벨별 생존 주기는 달라질 수 있으므로 원문 표 3.5·3.6의 사이클 변화는 [성장 구축](../references/combat-formulas.md#구축-기준-곡선에서-속성-총량-만들기)에서 확인한다.

성장 분할은 **속성별 예산의 계층적 배분**이다. 원문은 속성 분할이 육성 루트를 균등하게 나누는 것이 아니며, 유저 선호 우선순위(명시적 > 인지도가 높은 > 쉬운 > 랜덤성 육성 루트)에 따라 선호도가 높은 루트에 더 많은 속성을 넣으라고 한다(인쇄 73 / PDF 101). 원문은 벤치마크 분할과 글로벌 분할 중 하나를 쓴다(인쇄 73 / PDF 101).

- 벤치마크 분할은 레벨 성장 비율을 기준으로 다른 육성 루트의 비율을 비교해 정하며, 최종 비율의 합이 100%가 아니어도 된다(인쇄 73 / PDF 101). 원문 표 3.8은 공격·방어·체력 열이 각각 78%, 방어 관통·치명 공격 열이 65%다(인쇄 74 / PDF 102).
- 글로벌 분할은 캐릭터·장비·탈것 같은 큰 범주에서 한 번, 그 안의 하위 시스템에서 다시 나누며 최종 비율의 합이 반드시 100%여야 한다(인쇄 73–74 / PDF 101–102). 분할에는 가능한 한 백분율 계산 형식을 쓰는 것이 좋으며, 그러면 이후 수치 업데이트나 루트별 가중치 조절 때 백분율만 고치면 된다(인쇄 74 / PDF 102).
- 장비 부위 같은 세부 단위로 한 번 더 나눌 수도 있다(인쇄 77 / PDF 105). 세부 분할은 신발은 이동 속도, 무기는 방어 관통력처럼 게임에서 통용되는 합의된 설정을 따르고, 무기의 공격력은 장신구보다, 갑옷의 방어력은 다른 방어구보다 높게 둔다(인쇄 77–78 / PDF 105–106).
- 원문은 하위 밸런스를 유지하려면 1단계 공격·방어·체력의 총 분할 비율을 서로 같게 두라고 하며, 예를 들어 공격 총 분할 비율이 80%면 방어·체력도 각각 80%여야 하고 2단계 속성과 기타 속성은 실제 육성 요구에 따라 나눈다(인쇄 75 / PDF 103). 스킬 정리: 즉 속성 열을 모두 합쳐 100%인지 보는 것이 아니라 **각 1단계 속성의 경로별 합계가 같은 목표 총 분할 비율인지**를 검사하고, 형제 비율의 합이 부모 몫의 100%인지는 글로벌 분할에서만 검사한다.
- 두 방식 모두 게임 초기의 분할에 쓸 수 있고, 개발 후기나 버전 업데이트에는 주로 벤치마크 분할을 쓴다(인쇄 74 / PDF 102).

세분화는 각 육성 루트를 성장 횟수부터 성장으로 얻는 상세 속성 수치까지 정하는 단계이며, 그 전에 육성 모듈 마스터 플랜을 세운다(인쇄 78 / PDF 106). 원문 표 3.14의 열은 카테고리·횟수·종류·육성 플랜·속성 성장 플랜·비고다(인쇄 78–79 / PDF 106–107). 스킬 정리: 회당 증가량과 누적 속성은 이 플랜을 바탕으로 세분화 단계에서 정하는 값이며 표 3.14의 열은 아니다. 원문은 주류 육성 플랜을 성장형(육성 1회마다 고정 속성을 올림), 수집형(콘텐츠를 수집해 속성을 올리며 계속 육성할 수 없음), 하이브리드형(수집한 콘텐츠를 계속 육성할 수 있음)의 세 가지로 나눈다(인쇄 79 / PDF 107).

- 원문은 **성장 입상도**(1회 성장 간격)가 큰 루트는 구간마다 다르게 증가하는 곡선으로 성장 노드에서 도약감을 주고, 입상도가 작은 루트는 선형 증가 곡선을 쓰는 것이 좋다고 한다(인쇄 84 / PDF 112). 백분율 분배 방식에서 성장형 루트의 분배 비율은 누진적으로 커지며(인쇄 84 / PDF 112), 원문 예시는 50회 강화에서 1회 2%, 50회 100%다(인쇄 85 / PDF 113).
- 수집형 루트는 레벨과 수치의 관계를 알 수 없어 백분율 분배를 쓸 수밖에 없고, 레벨 벤치마크로 배분하면 수치가 넘치기 쉽다(인쇄 85 / PDF 113). 원문은 수집형을 ‘균등 분배’라고 설명하지만(인쇄 84 / PDF 112), 예시 표 3.23은 탈것마다 비율이 다르고 각 속성의 합을 70%로 같게 맞춰 남은 몫을 이후 새 탈것에 남긴다(인쇄 86 / PDF 114).
- 원문은 이 밖에 장비 재련처럼 육성 속성을 랜덤으로 얻고 유저가 필요에 따라 속성을 고르는 랜덤형도 든다(인쇄 87 / PDF 115). 랜덤형도 레벨 벤치마크나 백분율 분할 방식으로 세분화하되, 유저가 더 추구하거나 실제 수익이 더 높은 속성을 기준으로 넣고 부족한 속성은 암묵적으로 넣지 않은 것으로 나타낸다. 이 기준을 여러 유형 유저의 성장 데이터 시뮬레이션에 쓴다(인쇄 87–88 / PDF 115–116).
- 원문은 유저가 해당 레벨 속성의 100%에 도달하기는 거의 불가능하므로, 초기 설계에서는 일정 비율로 해당 레벨의 유저 속성을 측정한다고 한다(인쇄 89 / PDF 117). 원문 예시는 개방되지 않은 육성 루트의 비율을 빼서 실제 속성 비율을 구하고, 그 60%(합격점)를 참고 비율로 삼아 유저 속성 템플릿을 만든다(인쇄 89 / PDF 117). 레벨별 목표 비율은 [성장 구축](../references/combat-formulas.md#구축-기준-곡선에서-속성-총량-만들기)에 정리했다.

### AI/NPC: 템플릿, 고착 지점, 재검증

원문은 모든 NPC 속성의 정량화를 AI의 기본 응용으로 두며, 컨트롤에 능한 유저가 레벨이라는 수치 문턱을 넘어 버리는 게임에서 기본 응용만으로 난이도를 올리면 몬스터 속성을 올리는 수밖에 없어 컨트롤이 약한 유저의 경험이 나빠진다고 한다(인쇄 88–89 / PDF 116–117). 그래서 예측된 속성 수치에 도달하면 문턱을 넘을 수 있게 하는 특별한 메커니즘, 곧 AI의 고급 응용을 더한다(인쇄 89 / PDF 117).

NPC는 플레이어의 **몬스터 난이도 레벨에 대응하는** 속성을 인덱스로 삼아 공격·방어·체력의 유형별 기본 계수와 개체별 딜/생존 보정을 곱해 만든다(인쇄 92 / PDF 120). 일반·희귀·정예·보스 같은 유형은 목표 NPC 생존 주기와 플레이어 생존 주기로 먼저 정한다. 원문 예시의 표준 생존 주기 10턴에서는 일반/희귀/정예/보스가 각각 NPC 3/6/10/20턴, 플레이어 20/15/12/10턴이며, 공격 계수는 `표준 생존 주기 ÷ 플레이어 생존 주기`, 체력 계수는 `NPC 생존 주기 ÷ 표준 생존 주기`다(인쇄 91 / PDF 119). NPC 생존 주기가 짧을수록 전투 리듬은 빨라지고, 플레이어 생존 주기가 짧을수록 난이도는 높아진다(인쇄 90 / PDF 118). 몬스터 난이도 레벨은 게임 규칙에 따라 속성 인덱스값의 유형과 일치하도록 고르며, <월드 오브 워크래프트>에서는 유저의 아이템 레벨과 일치한다(인쇄 92 / PDF 120). 원문은 난이도가 비슷한 플레이에서는 속성 템플릿을 다시 설정하지 않고 재사용할 수 있다고 한다. 다만 템플릿이 적용되는 시나리오를 명확히 해야 한다(인쇄 93 / PDF 121). 이후 디폴트 매개변수를 최적화하면 재참조되는 데이터도 함께 바뀌므로 적용 가능한지 확인하고, 적용되지 않으면 새 디폴트 매개변수를 설정해야 한다(인쇄 93 / PDF 121). 원문은 시간이 있으면 가능한 한 모든 NPC에 디폴트 매개변수를 정의하라고도 한다(인쇄 93 / PDF 121).

**고착 지점**은 직업 메커니즘 실패나 레벨 격차가 큰 몬스터 사냥처럼 수치 밖의 요인이 수치의 문턱을 넘어 밸런스를 무너뜨리는 상황에 대비하는 고급 응용이다(인쇄 93 / PDF 121). 예를 들어 높은 난이도 NPC에 맞을 때 추가 피해를 주거나, 탱커의 보호막 기반 감소율을 조절한다(인쇄 93 / PDF 121). 원문은 고착 지점을 설계할 때 해결하려는 잠재적 위험과 추가로 생길 새 위험을 명확히 하고, ‘작은 문제’를 해결하려다 ‘큰 문제’를 만들지 않도록 주의하라고 한다(인쇄 94 / PDF 122). 스킬의 적용 지침: 이를 위해 발동 경계와 최대 보정도 함께 명시한다.

**세계 번영과 유저 매칭**은 원문의 또 다른 AI 고급 응용이다(인쇄 95 / PDF 123). 가상 유저 캐릭터로 팀원·상대·사회적 상호작용을 보완해 서로 다른 플레이어 유형의 콘텐츠 수요를 연결한다. 저자는 달성가·사교가·모험가형을 팀원 역할, 킬러형을 상대 역할로 예시하며, 속성 정량화에는 앞의 몬스터 난이도 설계 방식을 재사용한다. 실무 적용 시 어떤 참여 공백을 보완하는지, 어떤 유저 행동을 시뮬레이션하는지, 목표 난이도와 실제 경험이 맞는지 검증한다. 원문의 역사적 사례·효과 설명을 현재 서비스의 사실이나 보장된 성과로 인용하지 않는다.

원문은 현재 대부분 게임의 전투력 공식이 <월드 오브 워크래프트>의 장비 레벨식을 개선한 것이라고 소개한다(인쇄 96 / PDF 124). 이 식은 단일 속성이 높을수록 장비 레벨이 높아져, 속성 합이 같은 두 반지도 61.32와 65.21로 갈린다(인쇄 97 / PDF 125). 원문은 자기 게임의 특징에 맞게 이런 공식을 개선하라고 한 뒤, 이 책에서는 속성 수치에 속성 계수를 곱해 합산하는 선형식을 쓴다(인쇄 97 / PDF 125). 원문은 1단계 속성의 계수를 하위 밸런스의 속성 가중치(수치 비율)로 정하고, 2·3단계 속성의 계수는 해당 속성의 실제 수익으로 구한다(인쇄 98 / PDF 126). 예를 들어 하위 비율이 공격:방어:체력=`1:1:10`이면 계수는 `1, 1, 0.1`이다(인쇄 98 / PDF 126). 원문은 대부분 속성의 전투력 계수를 실제 수익을 기반으로 정하고, 협력 삼대장의 탱커·힐러·딜러 간 전투력 계수는 다를 수 있다고 한다(인쇄 99 / PDF 127). 스킬 정리: 직업별 속성 비율에 이 계수를 곱해 합산한 값이 같아도, 관통·치명·스킬 주기의 실제 피해 수익은 다를 수 있다. 전투력 수치가 같아도 리듬이 같다는 뜻은 아니다.

원문은 전투력 밸런스와 리듬 밸런스가 불일치하면 전투력 밸런스를 우선하고, 리듬 밸런스에서 손실된 속성 수익은 스킬 효과를 강화해 보완하라고 한다(인쇄 102 / PDF 130). 원문 예시는 직업별 속성 가중치를 보정해 전투력을 같게 맞추고, 표준 매개변수와의 차이를 스킬 보정 속성으로 돌린다(인쇄 103 / PDF 131). 스킬 정리: 즉 리듬 손실을 메우려고 속성을 다시 부풀리지 않는다. 원문은 이 계산을 **이론적 밸런스**로 보고, 전투 시뮬레이션으로 **실전 밸런스**를 이뤄야 진정한 밸런스라고 한다(인쇄 103 / PDF 131).

## 핵심 개념

- **공방체 삼대장**: 공격·방어·체력으로 이루어진 1단계 기본 전투 속성.
- **대공식 / 소공식**: 최종 결과를 내는 식 / 중간 단계를 계산하는 식. 백분율 위치에 따라 수익이 크게 달라진다.
- **생존 주기**: `체력 ÷ 피해`. 전투의 목표 턴 수와 난이도 판단의 공통 단위.
- **대미지 수익**: 공격 후 발생하는 최종 대미지 수치의 성장 양상.
- **방어 수익**: 공격이 일정할 때 방어 상승으로 얻는 피해 감소율 및 한계 가치.
- **가치 밸런스**: 서로 다른 속성 또는 직업의 수익을 공통 단위로 환산해 맞추는 것.
- **리듬 밸런스**: 비슷한 기능을 가진 직업 간 전투 능력(탱커의 생존, 딜러의 딜링, 힐러의 치유)의 균형이며, 직업마다 전투 과정은 달라도 ‘전투 수익’이 같아야 한다는 것이 판단 원칙이다(인쇄 101 / PDF 129).
- **성장 벤치마크**: 시간과 연결되어 모든 다른 성장 수치를 기준화하는 축.
- **고착 지점**: 잠재적 경험 문제를 막는 고급 보정 규칙.
- **성장 입상도**: 매번 업그레이드하는 시간 간격(성장 간격). 클수록 회당 속성 증가율과 자극이 커진다(인쇄 79 / PDF 107).
- **이론적 밸런스 / 실전 밸런스**: 계산 모델에서의 균형 / 시뮬레이션·플레이 결과로 확인된 균형.

## 판단 도구

- **먼저 리듬, 그다음 숫자**: 목표 전투 턴 수를 먼저 정한 뒤 HP와 피해를 역산한다.
- **표시 확률 대신 경로 확률**: 앞선 판정을 통과해야 가능한 효과라면 표시 확률이 아니라 경로 전체의 곱으로 가치를 계산한다.
- **공식은 성장 경험의 정책**: 같은 공격·방어 수치라도 공식과 상수가 유저가 어떤 속성을 추구하는지, 과금·격차가 얼마나 증폭되는지를 결정한다.
- **전투력은 계기판, 리듬은 주행감**: 전투력 합계가 같아도 DPS·생존·회복 주기가 다르면 플레이 경험은 다르다. 두 지표를 분리해 본다.

## 안티패턴

- **목적 없는 속성 추가**: 대응 공식·성장 경로·UI 이해가 없는 속성은 ‘계륵’이 되어 밸런스와 진입 난이도만 올린다. 원문은 유저가 이해하기 어렵고 기획자가 쓰기도 어려운 속성이 ‘계륵’이 되어 밸런스 난이도를 높인다고 한다(인쇄 34 / PDF 62). 새 속성에 목적이 없으면 게임이 어려워지고 유저의 입문 난이도가 올라간다고도 한다(인쇄 29 / PDF 57).
- **확률 우선순위 미문서화**: 명중 전 치명을 판정하는 등 불가능한 결과를 먼저 계산하면 기댓값과 설명이 어긋난다.
- **공식 하나를 표본 몇 개로 확정**: 고레벨·레벨 차이·다수전에서 곡선이 무너질 수 있으므로 구간 시뮬레이션 없이 상수를 확정하지 않는다.
- **전투력만 맞추기**: 같은 전투력이라도 폭딜·지속딜·생존·회복의 리듬 차이가 불공정하게 느껴질 수 있다.
- **고착 지점으로 큰 문제 만들기**: 한 악용을 막는 보정이 다른 직업·콘텐츠·매칭에 새 악용을 만드는지 발동 전후 데이터를 확인한다.

## 압축 재구성 예시

다음은 책의 10턴 사고방식을 사용한 **설명용 재구성**이다.

1. 목표 1:1 전투가 10턴이고, 기본 뺄셈식 `피해=공격-방어`를 쓰기로 한다.
2. 최소수 추론으로 `피해=1`, `체력=10`을 둔다. 피해 1을 만들기 위한 가장 작은 정수 조합은 공격 2, 방어 1이다. 따라서 초기 설계의 출발 비율은 공격:방어:체력 = `2:1:10`이다.
3. 명중 70%, 관통 30%, 치명 5%를 순서대로 판정하면 관통은 21%, 치명은 2.45%, 일반 명중은 46.55%다. 치명 5%를 그대로 전투력이나 아이템 가치로 쓰면 과대평가된다.
4. 보스의 목표 생존 주기를 20턴, 플레이어의 목표 생존 주기를 10턴으로 설정하면, 같은 레벨 플레이어 속성 템플릿에 체력 계수 `20÷10=200%`, 공격 계수 `10÷10=100%`를 출발값으로 둔다. 그 뒤 행동 패턴·방어·회복을 포함한 시뮬레이션 결과로 보정한다.

이 계산은 게임의 정답이 아니라 설계 출발점이다. 난수 분산, 스킬 쿨다운, 다수전, 플레이 숙련도를 포함한 실전 검증이 필요하다.

## 핵심 요약

1. 속성 하나를 추가하기 전, 그 속성이 어느 플로·공식·성장 루트·콘텐츠에서 가치를 내는지 연결한다.
2. 목표 생존 주기를 공통 단위로 사용해 공식·직업·NPC의 수치를 역산한다.
3. 확률 속성은 표시값이 아니라 우선순위와 동시 발생 규칙을 포함한 실제 기대 수익으로 평가한다.
4. 공식 선택은 공격·방어의 성장 수익과 PvP 격차의 정책 결정이므로 전 구간 곡선으로 검증한다.
5. 전투력, 역할 수익, 리듬을 모두 맞춘 뒤 시뮬레이션과 플레이로 이론적 밸런스를 실전 밸런스로 교체한다.

## 연결

- **1장**: 수치 기획의 전체 프로세스에서 전투 모델의 입력과 산출물을 정한다.
- **2장**: 장르·테마·목표 유저와 타깃 게임이 속성과 전투 경험의 선택 기준이 된다.
- **4장**: 경제·보상·소비 루트가 속성 총합 및 성장 분할과 결합해 실제 육성 속도를 만든다.
- **5장**: 이론적 전투 모델을 경제·육성·전투 결과로 검증하고 보정한다.
