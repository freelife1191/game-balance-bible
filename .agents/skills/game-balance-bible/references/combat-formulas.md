## 속성 총합과 변환

```text
총속성 = (초기속성 + 레벨업속성 + Σ장비 고정속성 + Σ스킬/버프 고정속성)
       × (1 + Σ백분율속성 + Σ스킬/버프 백분율속성)

장비속성합 = 장비 기본속성합 × (1 + 장비 기본 백분율속성합)
           + 장비 강화속성합 + 장비 재련속성합 + 장비 초월속성합
```

백분율은 `0.10`처럼 소수로 저장하고, 어떤 단계에 적용하는지 명시한다. 같은 10%라도 최종 대공식에 적용하면 전체 결과가 10% 증가할 수 있지만, 소공식에 적용하면 훨씬 작아질 수 있다.

대표 변환 형태:

```text
A = B × k                         # 선형 변환
A = B / (B + k)                   # 포화형 변환
A = B / (B + k1 × level + k2)     # 레벨 스케일 포화형
```

원문이 싣는 속성 변환 공식은 위 세 형태다(인쇄 44 / PDF 72). 스킬 정리: ‘선형 변환’·‘포화형 변환’·‘레벨 스케일 포화형’은 이 스킬이 붙인 이름이다. 원문은 0~1 범위가 필요한 속성에 ‘약간 더 어려운 일차함수’를 쓴다고 하며(인쇄 45 / PDF 73), 그 예가 아래의 피해 감소율 식이다(인쇄 46 / PDF 74). 원문의 <월드 오브 워크래프트> 일차함수 예는 `체력 = 인내 × 10`, `근접 공격력 = 직업계수 × 힘`이다(인쇄 45 / PDF 73). 포화형은 0~1 범위를 요구하는 감소율·확률에 유용하지만, 그 범위는 입력 조건에 달린다. `B≥0`, 상수항 `k≥0`(레벨형은 `k1×level+k2≥0`), 양수 분모일 때 0~1이다. `B=k=0`이면 정의되지 않는다. 한계 가치는 상수와 레벨 스케일에 따라 달라진다.

원문의 함수 선택 지침: 상수함수와 일차함수가 가장 자주 쓰이고, 이차함수는 적게, 삼차함수는 거의 쓰지 않는다(인쇄 45 / PDF 73). 이차함수는 속성이 빠르게 늘 때 곡선이 가팔라져 경험을 살릴 수 있지만 수치 밸런스 리스크도 높아 신중히 쓴다(인쇄 46 / PDF 74). 레벨·속성 구간마다 상수가 바뀌는 계단함수도 쓰며, 초등함수는 한계효용을 자주 나타내고 로그함수, 멱함수·지수함수 순으로 많이 쓴다(인쇄 46 / PDF 74). 어떤 함수든 모의 데이터를 대입해 `f(x)`와 결괏값의 치역을 미리 확인해야 하고, 초기 상수는 대부분 임시값이다(인쇄 47 / PDF 75). 원문 예시값: `대미지 감소율 = DEF/(DEF + 85×level + 400)`, 패링률 상수 5·0.04(인쇄 46 / PDF 74).

속성 변환을 정한 뒤에는 변환 결과도 총합식에 연결한다. 원문 인쇄 48쪽(PDF 76)의 수정식은 고정값 합산부에 `f(Σ속성 A)`를 추가한다. `f`는 해당 속성의 변환 함수다. 예를 들어 인내 총합을 체력으로 바꾸면 `인내 총합 × 10`을 체력 고정값 합산부에 넣은 뒤 체력 백분율을 적용한다. 이미 변환된 체력을 장비·초기 체력에 넣었다면 다시 더하지 않는다. 합산 후 변환과 개별 변환 후 합산은 비선형 함수에서 다를 수 있으므로 계산 순서를 고정한다.

## 스킬과 버프

원문은 스킬 계산 공식을 액티브 스킬·패시브 스킬·버프 계산 공식으로 나누며, 대부분의 게임은 이를 별도 유형으로 쓰지 않고 속성 계산 공식과 대미지 계산 공식에 넣어 스킬을 계산한다고 한다(인쇄 48 / PDF 76). 속성·스킬·대미지 계산 공식은 각각 기초·스킬·대미지 플로에 대응한다(인쇄 35 / PDF 63).

```text
스킬효과 = 기본대미지 × (1 + 스킬% + Σ시전자 버프% + Σ대상 버프%)
치유효과 = 기본치유 × (1 + 스킬% + Σ시전자 버프% + Σ대상 버프%)
보호막 = 체력 × k
패링 흡수 = 힘 × k
출혈 = 기본대미지 × k
점화 = 기본체력 × k
```

원문은 스킬 계산 공식이 스킬 플로의 보조 공식이라 속성·대미지 계산보다 매우 간단하고, 설계 초기에 전문적으로 설정할 필요 없이 스킬이 필요할 때 설정하면 된다고 한다(인쇄 49 / PDF 77).

같은 보너스 출처를 속성과 최종 배율에 두 번 넣지 않는다. 서로 독립된 공격력 버프와 최종 피해 버프는 의도적으로 공존할 수 있으며, 각각의 적용 단계와 순서를 명시한다. 위 예시의 `스킬%`는 기본 피해에 더하는 추가 비율이므로, 최종 피해 130%를 뜻하면 `0.30`이다. 다른 게임의 ‘스킬 계수 1.30’과 같은 저장 규칙으로 혼용하지 않는다.

**설명용 계산**: `ATK=100`, `DEF=100`, `D=ATK²/(ATK+DEF)`이면 기본 피해는 50이다. 공격력 +30%는 `130²/230≈73.478`이고, 최종 피해 ×1.30은 65로 서로 다르다. 두 독립 보너스를 의도적으로 적용하면 `73.478×1.30≈95.522`다. 선형식에서 성립하는 배율 치환을 비선형식에 그대로 적용하지 않는다.

## 확률 판정

확률론 알고리즘에서 우선순위 `명중 → 관통 → 치명`이라면:

```text
P(명중 성공) = h
P(관통) = h × p
P(치명) = (h - h×p) × c
P(일반 명중) = h - P(관통) - P(치명)
P(빗나감) = 1 - h
P(관통) + P(치명) + P(일반 명중) = h
```

`명중 성공`은 관통·치명·일반 명중을 포함하는 상위 사건이다. 배타적 결과 확률의 합계에는 이 상위 사건을 다시 더하지 않는다. 이 식에서 p와 c는 앞선 경로를 통과한 뒤의 조건부 판정 확률이다.

예시: `h=.70`, `p=.30`, `c=.05`이면 관통 21%, 치명 2.45%, 일반 명중 46.55%, 빗나감 30%다(인쇄 41 / PDF 69). 이 값은 **책의 예시를 압축 재계산한 것**이며, 관통과 치명이 동시 결과로 모델링되는 설계에는 그대로 적용하지 않는다.

원문은 확률론의 범위 확장 예로 명중 70%, 방어 관통 50%, 치명 50%를 들어 관통 35%, 치명 12.25%, 일반 공격 22.75%라고 한다(인쇄 41 / PDF 69). 원문 표기 / 계산값: 치명 12.25%는 `(70% - 35%) × 35%`로 구한 값이고, 같은 `(70% - 35%)`에 치명 50%를 곱하면 17.5%다.

원문은 <월드 오브 워크래프트>가 공격 판정에 원탁 이론 알고리즘을 쓴다고 하며, 우선순위가 높은 속성의 합이 100%를 넘으면 우선순위가 낮은 결과가 밀려난다고 한다(인쇄 41 / PDF 69). 원문 예시는 회피 30%·방어 관통 30%·치명 5%이면 일반 공격이 35%이고, 회피 50%·방어 관통 50%·치명 5%이면 치명이 0%가 되는 경우다(인쇄 41–42 / PDF 69–70).

스킬의 적용 지침: 원탁 이론 알고리즘에서는 모든 결과 칸의 합이 1을 초과하지 않게 우선순위대로 배치한다. 초과분으로 밀려난 결과와 비어 있는 일반 결과 칸을 수치표에 모두 표시한다.

## 대미지 모델

원문 인쇄 49–56쪽(PDF 77–84)의 비교식은 다음과 같다.

```text
기본 뺄셈:          D = ATK - DEF
업그레이드 뺄셈:    D = ATK - (ATK × DEF)/(K + DEF)
곱셈:               D = ATK × (1 - R)
                    R = SHIELD/(SHIELD + K1×LEVEL + K2)
나눗셈:             D = ATK²/(ATK + DEF)
```

`나눗셈` 식의 제곱은 인쇄 51쪽(PDF 79쪽) 렌더로 확인했다. 텍스트 추출에서는 위첨자가 깨져 `공격 수치'`처럼 보인다. 보호막을 방어로 해석하는 것은 책의 비교 예시에서만 사용한 가정이므로, 게임 구현에서는 `SHIELD`와 `DEF`를 구분한다.

피해 감소율(DR) `DR=(A-D)/A`(공격 A, 대미지 D)와 ‘100%를 초과할 수 없다’는 조건은 원문 표 3.4에 붙은 옮긴이 주의 보충이다(인쇄 54 / PDF 82). 스킬 정리: 비교 기준 공격 `A>0`에서 산출하며, 감소만 있는 비교 모델에서는 `0≤D≤A`이므로 `DR`도 0~1이다. 원문 인쇄 59쪽(PDF 87)은 곱셈식의 `1-R`을 감소율로 부르지만, 이는 피해 잔존 배율이며 감소율은 `R`이다. 범위를 벗어나면 원시 값을 보존해 취약·증폭 효과인지 오류인지 확인하고, 클램프는 구현 정책으로 별도 정의한다. 업그레이드 뺄셈과 곱셈의 상수는 방어 수익이 급격히 낮아지기 시작하는 구간을 정하므로, 기획 의도 없이 복사하지 않는다. 원문 예시값은 업그레이드 뺄셈 `K=700`(인쇄 50 / PDF 78), 대미지 수익 비교의 `K=1200`과 곱셈 `K1=50, K2=200`(인쇄 52 / PDF 80), 방어 수익 비교의 `K=400`과 곱셈 `K1=30, K2=400`(인쇄 54 / PDF 82)이다. 성장 구축 사이클 계산의 업그레이드 뺄셈은 `K=2000`(인쇄 70 / PDF 98), 전투력 계수 예시는 `K=1000`(인쇄 98 / PDF 126)이다. 같은 공식도 비교 목적에 따라 상수가 다르므로 어느 값도 기본값으로 쓰지 않는다.

뺄셈식의 원시 피해가 음수라고 음수 생존 주기를 계산하지 않는다. 실제 피해의 하한이 0인지, 최소 피해가 있는지는 프로젝트 규칙으로 정한다. 모든 분모는 0이 아닌 유효 범위에서 계산한다.

## 생존 주기·직업 가치·NPC

```text
생존 주기 근사(타격 단위) = HP / 1회 실제 피해
필요 타격 수(고정 피해) = ceil(HP / 1회 실제 피해)
생존 시간 근사(초) = HP / DPS
정확한 처치 시각(고정 간격) = 첫 타격 시각 + (필요 타격 수 - 1) / 초당 타격 수
전투력 = Σ(속성값 × 속성계수)

NPC_ATK = Player_ATK[monsterDifficultyLevel] × defaultAtk[type] × damageModifier
NPC_DEF = Player_DEF[monsterDifficultyLevel] × defaultDef[type] × survivalModifier
NPC_HP  = Player_HP[monsterDifficultyLevel]  × defaultHp[type]  × survivalModifier
```

위 NPC 세 식은 원문 표 3.28 노트의 몬스터 속성 공식이다(인쇄 92 / PDF 120). 위 생존식은 `HP>0`, 양수 고정 피해, 회복·다른 피해원 없음이라는 단순 모델이다. HP가 이미 0 이하면 생존 시간은 0이다. 실제 피해가 0 이하이고 다른 처치 수단이 없으면 나눗셈하지 않고 ‘처치 불가/∞’로 표시한다. 변동 피해·치명타·회복이 있으면 평균 초당 피해(DPS) 식은 근사이며 정확한 처치 시점은 전투 경로로 검증한다.

**설명용 계산**: HP 100, 타격당 20, 초당 2회면 5타격과 DPS 근사 2.5초다. 첫 타격이 0초면 실제 마지막 타격은 2초, 첫 타격이 0.5초 뒤면 2.5초다. NPC 계수를 비교할 때도 플레이어와 NPC의 생존 주기 단위를 일치시킨다.

원문 표 3.27 노트의 NPC 출발 규칙은 `공격 계수 = 표준 생존 주기 ÷ 플레이어 생존 주기`, `체력 계수 = NPC 생존 주기 ÷ 표준 생존 주기`다(인쇄 91 / PDF 119). 원문 표 3.27은 표준 생존 주기 10턴에서 보스를 NPC 20턴·플레이어 10턴으로 두고 체력 계수 200%를 싣는다(인쇄 91 / PDF 119). 스킬 정리: 행동 패턴, 회복, 군중 제어, 파티 규모가 들어가면 이 비율만으로 난이도를 보장할 수 없다.

## 성장 구축·분할·세분화

### 구축: 기준 곡선에서 속성 총량 만들기

원문의 선형 예시는 레벨 `L`에서 `ATK=6L`, `DEF=6L`, `HP=60L`이다(인쇄 70 / PDF 98). 성장식과 피해식을 같이 넣어 전투 사이클을 다시 계산한다. 2단계 속성을 추가하면 그 효과(예: 치명 피해 +100%, 관통 피해 +50%)까지 대미지 플로에 넣어 사이클을 재계산한다(인쇄 71 / PDF 99). 원문 표 3.5는 `1:1:10` 선형 성장을 업그레이드 뺄셈(`K=2000`)에 넣어 사이클이 1레벨 10.03턴에서 100레벨 13턴으로 늘어나고(인쇄 70 / PDF 98), 표 3.6은 치명 공격·방어 관통을 레벨당 0.5%씩 100레벨 50%까지 더해 사이클이 9.95턴에서 6.93턴으로 줄어든다(인쇄 71 / PDF 99). 스킬 검산: 표 3.6의 사이클은 두 효과를 독립 기대 배율 `(1+치명률×1.0)×(1+관통률×0.5)`로 곱한 값과 0.01턴 이내로 맞는다. 스킬 정리: 1단계 비율을 고정해도 비선형 피해식과 2단계 속성 때문에 생존 주기가 변하므로 레벨별 사이클을 따로 검산한다. 이는 책의 예시이지 임의 게임의 기본값이 아니다.

유저 속성 템플릿은 다음처럼 **기준 속성, 개방 루트 비율, 목표 비율**을 분리한다. 개방 루트 비율은 원문 표 3.26의 ‘속성 비율’로, 해당 레벨에서 개방되지 않은 육성 루트의 비율을 빼서 구한 ‘실제 속성 비율’이다(인쇄 89 / PDF 117). 스킬 정리: 이름과 달리 유저 관측값이 아니라 개방 루트로 계산한 설계값이다.

```text
userStat[s, L] = standardStat[s, L] × openRatio[L] × targetRatio[L]
```

원문 표 3.26은 3레벨의 개방 루트 비율 20%, 목표 비율 60%, 결과 2.16을 싣는다(인쇄 90 / PDF 118). 스킬 검산: 3레벨 기준 공격력 18을 입력으로 두면 `18 × .20 × .60 = 2.16`으로 재현된다. 원문 표 3.26의 목표 비율은 1~2레벨이 100%, 3레벨부터 60%인 원문 예시값이다(인쇄 90 / PDF 118). 원문은 이 표를 임시 템플릿으로 보고, 수치 검증으로 얻은 유저의 실제 성장 데이터로 교체하라고 한다(인쇄 90 / PDF 118). 스킬 정리: 세 값을 섞지 않아야 콘텐츠 난이도용 템플릿을 실제 성장 데이터로 교체할 수 있다.

### 분할: 속성별 예산을 경로에 배정하기

분할은 각 속성 `s`의 총 성장치 `T[s]`를 모듈 트리에 배정하는 연산이다.

```text
moduleStat[s] = T[s] × globalShare[module, s]
submoduleStat[s] = moduleStat[s] × localShare[submodule, s]
itemStat[s] = submoduleStat[s] × itemShare[item, s]
```

글로벌 분할에서는 형제 노드의 `globalShare` 또는 `localShare`가 **동일 속성, 동일 부모** 안에서 합계 1이어야 한다(부모 몫이 0%인 속성 열은 0%). 원문은 글로벌 분할의 최종 비율 합이 반드시 100%여야 한다고 한다(인쇄 74 / PDF 102). 벤치마크 분할은 레벨 성장 비율을 기준으로 다른 루트를 비교해 정하므로 합이 100%가 아니어도 되며(인쇄 73 / PDF 101), 원문 표 3.8의 공격·방어·체력 열 합은 각각 78%다(인쇄 74 / PDF 102). 또 원문은 하위 밸런스를 유지하려면 1단계 공격·방어·체력의 전체 분할 비율을 같게 두라고 한다. 예컨대 공격 경로의 총 분할이 80%면 방어와 체력의 경로 총 분할도 각각 80%여야 한다(인쇄 75 / PDF 103). 따라서 여러 속성 열을 통틀어 100%인지 검사하는 것이 아니라, 각 1단계 속성별 합계와 그 합계 간의 균형을 확인한다.

예컨대 공격 총량 12, 장비 강화 비율 10%, 무기 비율 40%이면 무기 강화 공격력은 `12 × .10 × .40 = .48`이다(인쇄 82 / PDF 110). 이 곱셈은 전체 성장 예산을 중복 지급하지 않게 한다.

레벨 기준이 있는 성장형 루트는 레벨에 대응하는 `T[s]`를 인덱싱하거나(레벨 벤치마크 방식), 백분율 분배 방식에서는 누진적으로 커지는 분배 비율로 나눈다(인쇄 80·84 / PDF 108·112). 레벨 대응이 없는 수집형 루트는 항목별 백분율로 `T[s]`를 분배하며, 레벨 벤치마크로 배분하면 수치가 넘치기 쉽다(인쇄 85 / PDF 113). 수집형은 각 속성 열의 합을 같게 맞추되 100%를 다 배분하지 않아도 된다. 원문 표 3.23은 탈것 10종의 각 속성 합을 70%로 두어 이후 새 탈것을 위한 여지를 남긴다(인쇄 86 / PDF 114). 표의 `총합` 열은 항목의 상대적 크기(탈것의 우열·가격 참고)를 보여 줄 수 있지만, 속성별 예산 검사는 각 열의 합으로 한다(인쇄 86 / PDF 114). 새 모듈을 더할 때 기존 분할 비율을 함께 재조정하지 않으면 총 예산이 늘어난다.

### 세분화: 횟수와 지급 곡선 고정하기

마스터 플랜(원문 표 3.14)에는 루트별 `횟수`, `종류`, `육성 플랜`, `속성 성장 플랜`, `비고`를 둔다(인쇄 78–79 / PDF 106–107). 원문 예시에서 속성 성장 플랜은 선형 성장·한계효용체증·한계효용체감이고, 비고에는 성장 간격과 과금 정도를 적는다(인쇄 78–79 / PDF 106–107). 성장 입상도(1회 성장 간격)가 큰 루트는 구간별 증가, 입상도가 작은 루트는 선형 증가가 원문의 선택 기준이다(인쇄 79·84 / PDF 107·112). 레벨 벤치마크의 대응 간격이 균등하면 해당 루트의 속성 증가도 같은 비율 추세가 되고, 구간별로 다른 간격을 대응시키면 구간별 성장 추세가 된다(인쇄 83 / PDF 111). 강화처럼 누적 분배율 `q[n]`을 정한 경우는 다음처럼 기록한다.

```text
upgradeTotal[s, n] = T[s] × systemShare[s] × upgradeShare[s] × q[n]
increment[s, n] = upgradeTotal[s, n] - upgradeTotal[s, n-1]
```

`q[n]`이 누적 비율인지 회차 비율인지 명시하지 않으면 지급값을 누적해서 두 번 더하는 오류가 난다. 원문의 50회 강화 예시에서 1회는 누적 2%, 50회는 누적 100%다(인쇄 85 / PDF 113).

## 전투력 계수와 직업 수익

```text
power = Σ(stat[s] × coefficient[s])
```

하위 밸런스가 공격:방어:체력=`1:1:10`이면 책의 예시는 `coefficient=(1, 1, .1)`이다. 힐러 `1:1:10`, 탱커 `.5:1.1:14`, 딜러 `1.5:.85:6.5`는 성장 구축의 표 3.7에서 처음 나오고(인쇄 72–73 / PDF 100–101), 표 3.31에서 모두 가중치 3이 된다(인쇄 99–100 / PDF 127–128). 표준 직업 1:1:8 기준의 딜러 `1.5:0.75:6`(인쇄 63 / PDF 91)은 이와 다른 예시다. 이것은 역할별 전투력 **표시값**을 맞추는 계산이다.

2·3단계 속성 계수는 실제 피해 수익으로 구한다. 원문의 예시는 100레벨 `ATK=600`, `DEF=600`, 업그레이드 뺄셈 상수 1,000, 치명 시 최종 피해 +100%, 관통 시 대상 방어 30% 감소를 가정한다(인쇄 98 / PDF 126).

- 치명 50%는 `600×100%×50%=300 ATK` 수익이므로 치명 1%의 계수는 `300÷50=6`이다. 관통 50%는 `600×12.67%×50%=38 ATK` 수익이라 1% 계수는 `38÷50=.76`이다(인쇄 98 / PDF 126).
- 스킬 검산: 이 조건에서 관통은 피해를 375에서 약 422.5로 약 12.7% 늘리므로 원문의 12.67%는 이 피해 증가율로 보이며, 원문은 이 비율을 공격력 600에 곱했다. 다른 입력에 재현할 때는 같은 방식으로 증가율을 먼저 구한다.
- 이 계수를 공격력에 따라 매번 키우면 후반 전투력이 과도하게 팽창할 수 있다는 것이 원문의 경고다(인쇄 98–99 / PDF 126–127).
- 원문은 계산한 수익이 테크닉·전략으로 달라질 수 있어 주관적 판단으로 계수를 고칠 수도 있다고 하며(인쇄 99 / PDF 127), 감속·기절 같은 제어 스킬 효과의 전투력은 주로 전투력 구간과 수치 범위에 따라 정한다고 한다. 원문 예시값은 감속 200, 기절 500이다. 효과형 속성의 전투력은 가능하면 실제 전투 수익으로 정량화하고, 정량화하기 어려우면 상황에 따라 평가한다(인쇄 101 / PDF 129).

리듬 수익을 맞추기 위한 관통·치명 조합과 전투력 표시값이 충돌할 수 있다. 원문의 직업 예시처럼 전투력 가중치를 다시 맞춘 뒤, 차이는 스킬 효과로 보정한다(인쇄 102–103 / PDF 130–131). 원문 예시값: 도적(관통 39.5%·치명 15%), 폭딜 법사(치명 25%), 방관 사냥꾼(관통 80%·치명 4.8%)은 관통·치명 수익이 모두 1.688인 표준 매개변수에서 전투력이 123.02·153·92.6으로 갈린다(인쇄 102 / PDF 130). 원문은 속성 가중치를 보정해 세 직업의 전투력을 모두 75로 맞추고, 표준 매개변수와의 차이(예: 도적 관통 7.92%·치명 7%)를 스킬 보정 속성으로 돌린다(인쇄 103 / PDF 131). 원문은 이 설정이 저자의 경험에 따른 것이라 정확하지 않을 수 있다고 밝히므로(인쇄 103 / PDF 131), 해당 게임의 승률·처치 시간·생존 시간으로 재검증한다.

## 고착 지점 점검

```text
보호막 감소율 = SHIELD/(SHIELD + K1 + K2×attackerLevel)

몬스터 레벨이 유저 레벨보다 높을 때:
adjustedDamage = damage + damage × (monsterLevel - playerLevel) × levelGapCoefficient

상대 전투력이 더 높을 때:
profitRate = ((targetPower - playerPower)/targetPower) × K1 + K2
adjustedDamage = damage × (1 + profitRate)
```

레벨 차 보정은 인쇄 93쪽(PDF 121) 이미지에서 덧셈식과 상위 몬스터 조건을 확인했다. 설명용 계산: 피해 100, 몬스터 20레벨, 유저 10레벨, 계수 0.05면 보정 피해 150이다. 전투력 차 보정은 별도 사례이며 레벨 차를 대체하지 않는다. 원문 예시값은 대상 전투력 > 유저 전투력일 때 `K1=0.2`, `K2=0.5`이고, 그렇지 않으면 `K1=0`, `K2=0`으로 일반 대미지 계산을 쓴다(인쇄 94 / PDF 122). 스킬 검산: 이 예시는 전투력 차가 아주 작아도 `profitRate`가 0.5 이상이므로 경계에서 피해가 1.5배로 뛴다. 두 식을 함께 쓸지는 게임 명세로 정한다. 원문 식의 발동 조건을 지키고, 계수·상한·중첩 여부는 프로젝트 규칙으로 정의한다. 고착 지점마다 최대 보정과 악용 시나리오를 검증한다.
