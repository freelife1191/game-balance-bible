## 근거의 세 종류

문장·수식·그래프를 아래 세 범주로 나눈다. 서로 섞이면 책의 사실, 설명을 위한 가정, 프로젝트 제안의 책임 범위가 흐려진다.

| 구분 | 뜻 | 확인 방법 | 예 |
|---|---|---|---|
| **원문 근거** | 책이 실제로 제시한 정의·수치·사례 | 인쇄 쪽수, PDF 쪽수, 표·각주·적용 조건을 대조 | `피해=A²/(A+D)`라는 책의 나눗셈 예시 |
| **설명용 예시** | 개념을 설명하려고 새로 둔 값과 상황 | 새 예시임을 밝히고 산술·단위를 독립 계산 | `A=130`, `D=100`을 넣어 피해를 계산 |
| **실무 보완** | 프로젝트에 적용하려는 정책·권고 | 가정, 데이터, 목표 경험, 한계를 기록 | 로그 분포와 이탈 구간을 함께 비교 |

> [!NOTE]
> 책의 게임 사례와 시장 수치는 집필 당시의 맥락이다. 현재 서비스의 기준으로 바꾸어 단정하지 않는다. 설명용 예시가 맞더라도 책에 있던 값이라는 근거는 되지 않는다.

원문 근거는 [출처 지도](../.agents/skills/game-balance-bible/references/source-map.md)에서 장·인쇄 쪽수·PDF 쪽수와 추출 한계를 확인한다. 책의 전체 PDF는 현재 이 저장소에 포함되어 있지 않다. 원문을 다시 대조해야 하는 경우에는 합법적으로 접근 가능한 원본으로 확인한다.

## 수치와 공식의 검증 순서

수식에는 기호, 단위, 적용 순서, 정의역을 함께 적는다. `HP / 1회 실제 피해`는 **타격 수**이고, `HP / 초당 피해`는 **시간(초)**이다. 단위가 다른 두 값을 같은 결론에 섞지 않는다.

1. **원문·출처 대조** — 표의 행·열, 소수점, 부호, 분수, 반올림, 변수 정의를 확인한다. 텍스트로 모호한 표·수식은 원본 PDF 페이지 이미지로 재확인한다.
2. **전제 확인** — 확률이 독립인지 순차 판정인지, 보정이 가산인지 곱연산인지, 기간과 모집단이 같은지 확인한다.
3. **독립 계산** — 별도 식이나 계산기로 합계, 기대값, 가중 평균, 누적값을 다시 계산한다. 표시 반올림과 산술 오류를 구분한다.
4. **경계값 확인** — 분모 0, 음수·범위 밖 확률, 0 소비량, 초기값 누락, 공유 자원의 이중 사용을 검사한다.
5. **판정 기록** — 원문 표기, 추출 오류, 설명용 예시 오류, 실무 가정 차이를 구분한다. 원문 오기로 보이면 임의로 고치지 않고 근거와 정합 계산을 같이 남긴다.

### 독립 사용 시험과 직접 검산

스킬 사용 시험에는 의도한 답을 미리 주지 않는다. 스킬이 필요한 파일을 찾고, 가정과 단위를 밝히며, 풀이를 재현 가능하게 만드는지를 본다.

```text
$game-balance-bible
체력 101인 적을 한 번에 20씩, 초당 2회 공격한다.
필요 타격 수와 첫 타격이 0초일 때 처치 시각을 계산해 줘.
사용한 가정, 단위, 관련 근거 파일을 밝혀 줘.
```

> [!TIP]
> 위 사례의 직접 검산은 `ceil(101 / 20) = 6회`다. 첫 타격이 0초이고 초당 2회이면 간격은 `1/2초`, 처치 시각은 `(6−1)/2 = 2.5초`다. 이는 해당 사례의 산술·가정 확인이며 모델 응답 전체의 증명은 아니다.

### 재현 가능한 수치 회귀

프로젝트의 표준 라이브러리 Python 재현기는 스킬 예시의 산술과 명시한 모델 불변식을 검증한다.

```bash
python3 output/skill-review/numeric_regression.py
```

이 명령은 `output/skill-review/numeric-regression-results.json`을 **갱신**한다. 실행 전후 변경을 검토하고 `status`, 실패 항목, `limitation`을 읽는다. 현재 기준은 산술 단언 **64개**, 확률 격자 **1,331개 조합**, 피해식 동치 **24개**다. 이 재현은 전체 원문 판독이나 실제 호스트 호출을 수행하지 않는다.

## 구조와 포함 범위

정본 스킬은 `.agents/skills/game-balance-bible`이며 Claude Code에는 다음 상대 심볼릭 링크 하나를 둔다.

```text
.claude/skills/game-balance-bible
→ ../../.agents/skills/game-balance-bible
```

스킬 묶음은 Markdown 지식 파일 **16개**와 호스트 메타데이터 `agents/openai.yaml`을 합쳐 **17개 파일**이다.

| 구성 | 수량 | 역할 |
|---|---:|---|
| `SKILL.md` | 1 | 호출 규칙, 8장 색인, 적용 원칙 |
| `chapters/ch01`~`ch08` | 8 | 준비·전투·경제·검증·수익화·시각화·모듈화 지식 |
| `references/*.md` | 4 | 전투 공식, 경제 모델, 출처·페이지 지도, 질문별 자료 지도 |
| `glossary.md`, `patterns.md`, `cheatsheet.md` | 3 | 용어, 실무 절차, 빠른 참조 |
| `agents/openai.yaml` | 1 | Codex 호스트 메타데이터 |

**구조 확인 체크리스트**

- [ ] 정본 경로와 Claude 링크가 모두 존재하고 링크 대상이 정본 경로인지 확인한다.
- [ ] 8개 장 파일과 참고 파일 4개가 빠지지 않았는지 확인한다.
- [ ] `SKILL.md`의 장 색인과 실제 파일명이 일치하는지 확인한다.
- [ ] 출처 지도에 장별 인쇄 쪽수·PDF 쪽수·추출 한계가 있는지 확인한다.
- [ ] 새 내용은 원문 근거·설명용 예시·실무 보완 중 어디에 속하는지 표시한다.

> [!IMPORTANT]
> 파일이 발견되는 것과 실제로 계산을 수행하는 것은 다르다. 구조 확인은 경로·링크·파일 구성만 확인하며, 로그인 상태나 호스트 런타임을 검증하지 않는다.

## 수식·자원·KPI 점검표

### 전투·확률·TTK

| 점검 항목 | 확인 질문 |
|---|---|
| 피해식 | `A`, `D` 등 기호의 뜻과 분모가 0이 될 수 있는 조건을 적었는가? |
| 적용 순서 | 고정 피해, 가산 보너스, 비율 보너스, 최종 배율의 순서를 고정했는가? |
| 확률 | `0≤p≤1`인지, 독립·순차·원탁 판정 중 어느 모델인지 밝혔는가? |
| 기대 피해 | 결과 확률의 합이 1인지, 미스·치명·관통이 겹치거나 누락되지 않는지 확인했는가? |
| 비율 정의 | 표5.15의 1회 피해 비율과 표5.13의 생존 턴 비율을 구별했는가? |
| TTK | 타격 수와 시간 단위를 구분하고, 첫 타격 시각·공격 속도·회복·보호막 조건을 적었는가? |

### 경제·공유 자원

| 점검 항목 | 확인 질문 |
|---|---|
| 기간 | 일간·주간·시즌 누적을 같은 기준 기간으로 환산했는가? |
| 잔여량 | `생산−소비`와 초기 보유량을 포함한 실제 잔고를 구별했는가? |
| 공유 제약 | 동일 재화를 여러 기능이 동시에 쓸 때 총 공급을 초과 배분하지 않았는가? |
| 소비 0 | 잔여 비율의 분모가 0이면 지표를 정의하지 않거나 별도 처리했는가? |
| 기대값 | 드롭 확률과 수량, 시도당·성공당 기준을 분리했는가? |

### 수익화·KPI

| 지표 | 반드시 맞출 조건 |
|---|---|
| ARPU·ARPPU·PR | 분자·분모가 같은 기간과 같은 이용자 집합인가? |
| LTV | ARPU, 이탈률, 집계 주기, 일정성 가정을 명시했는가? |
| CPA | 획득 비용과 유입 이용자의 귀속 기간이 같은가? |
| 비교 | 과금 수준·직업·레벨·이용자군을 섞지 않고 분리했는가? |
| 회수 시점 | LTV와 구별해 코호트별 누적 수익·비용 및 이탈·유입 경로를 정의했는가? |

> [!NOTE]
> 수치가 매끈해도 목표 경험이 맞는지는 별도 플레이 시험이 필요하다. 그래프, 전투력, KPI는 판단 재료이며 단독으로 밸런스를 보증하지 않는다.

## 호스트 사용 시험

실제 호스트 시험은 **발견**, **지식 탐색**, **계산**으로 분리한다.

| 시험 | 확인할 것 | 통과 기준 |
|---|---|---|
| 발견 | 새 세션의 목록·호출 경로 | `game-balance-bible` 이름과 정본 경로가 확인됨 |
| 지식 탐색 | 장 번호·주제 질문 | 관련 장·참고 파일과 한계를 밝힘 |
| 계산 | 답을 주지 않은 작은 문제 | 가정·단위·계산 순서가 직접 검산과 일치 |

> [!NOTE]
> `output/skill-review/multi-agent-compatibility.json`의 기록에서는 Claude Code가 스킬 **발견**에는 통과했지만 OAuth 세션 만료로 계산 스모크가 `BLOCKED_AUTH`였다. Antigravity 계산 스모크는 통과했으며 `936/11`(약 `85.0909`), 6회, 2.5초를 보고했다.
>
> 이는 당시 환경의 기록이다. Claude Code·Antigravity는 이번에 재실행하지 않았다. 새 세션·새 모델·다른 호스트에서도 자동으로 재현된다는 뜻이 아니다.

2026-10-12의 [Codex 실제 호출 기록](../output/skill-review/codex-host-smoke.json)은 Codex CLI 0.162.0의 읽기 전용 세션 **1회**다. 기대 답을 제공하지 않은 요청에서 스킬 이름으로 정본을 찾고, 관련 장·레퍼런스를 읽고 Python으로 계산했다. HP385, 타격6회, 정확한 처치2.5초와 DPS 근사2.525초, 월 ARPPU194.8·ARPU19.48·근사 LTV97.4가 직접 검산과 일치했다. 실제 회수 월은 입력 부족으로 확정하지 않았다. Codex App UI·다른 호스트·전체 고급 예시의 시험은 포함하지 않는다.

인증 실패나 권한 거부가 나면 결과를 `BLOCKED_AUTH` 또는 환경 차단으로 기록한다. 토큰을 출력하거나 인증을 우회하지 말고, 원문 대조와 독립 계산처럼 가능한 검사를 계속한다.

### 프롬프트 표본 검증

2026-10-12에는 README2개·고급 예시3개를 **각각 독립된 Codex CLI 세션**에서 시험했다. 문서의 프롬프트에 읽기 전용 실행·검산·응답 길이 조건만 붙였고 기대 답은 주지 않았다. 별도 검수 에이전트도 기대값 파일을 읽지 않고 입력과 스킬 자료로 결과를 확인했다. [표본 검증 기록](../output/skill-review/prompt-sample-validation.json)에 정확한 입력·응답·판정을 남긴다.

| 표본 | 확인된 계산·판단 |
|---|---|
| README 전투 | 피해50·20타·정확한 처치9.5초와 DPS근사10초; 목표 만족으로 조정 없음 |
| README 재화 | 생산760·계획 잔여−140·잔여비율−15.56%; 초기 재고 포함 부족40과 실제 지출 구분 |
| 고급 1장 C: 확률 보상 | 평균은 같으나 B의 30일 분산3000·목표 달성확률57.22%; 추가 가정과 실제 달성률 구분 |
| 고급 5장 B: 공유 지갑 | 레벨4; 장비 우선2단계·스킬1단계, 소비130·잔여30; 가능한 정수 조합10개 |
| 고급 8장 A: 모델 맵 | 10개 모델·소비/생산 분리·8→4 피드백·전투 기본 모델의 필요 시 호출 |

**응답 정확성은5/5 통과했지만 실행 증거는 별도로 판단했다.** 수치 예시 중3개는 “도구로 검산했다”는 응답과 달리 이벤트에서 계산 호출을 확인할 수 없었다. 공유 지갑의 실제 Python 검산은 조합 수를 처음9개로 잘못 단언해 실패했으나10개로 수정·재실행했고 최종 답변은 정확했다.

따라서 [실행 증거를 요구하는 후속 요청](advanced-usage.md#계산-결과를-실행-증거로-확인하기)을 보완했다. 해당3개 계산을 후속 세션1회에서 재검산해 Python의 실제 출력과 단언 통과를 확인했다. 처음 응답의 실행 증거 미확인 상태를 소급해 통과로 바꾸지는 않는다. 전체 고급 예시·다른 호스트·실제 게임 결과의 검증은 아니다.

이후 스킬의 진입점·실무 패턴·질문별 자료 지도에도 실행 검산 조건을 반영했다. 개념 설명은 실행을 강제하지 않고, 실행 검산에는 관측 출력·실패·미실행을 구분한다. 조회·공유 지갑은 조합 개수보다 비용 제약·목록·잔여량을 먼저 검증한다.

보완 후 새 입력의 독립 세션2개도 통과했다. 실제 Python 실행에서는 5일 기대 생산15·분산15·목표 달성확률76.26953125%, 공유 지갑의 장비/스킬2/1단계·잔여0·가능 조합8개를 확인했다. 계산 도구를 금지한 별도 요청에서는 7타·처치2초를 식으로 확인하고 실행 검산과 실제 플레이를 미실행으로 표시했다. 입력·출력·독립 검수·스킬17개 파일의 현재 해시는 기록의 `post_validation_refinement`에 있다. 과거 보고서의 해시는 각 시험 당시 버전으로 유지한다.

## 보고서 읽기와 완료 기준

검수 결과에는 최소한 다음을 남긴다.

| 항목 | 기록할 내용 |
|---|---|
| 대상 | 스킬 경로, 확인한 파일 범위, 원문 식별자 |
| 근거 | 페이지·표·적용 조건, 설명용 예시, 실무 보완의 구분 |
| 계산 | 공식, 변수·단위, 기간, 가정, 독립 검산과 허용 오차 |
| 구조 | 정본 경로, Claude 링크, 17개 파일과 8개 장의 확인 결과 |
| 호스트 | 시험 프롬프트, 발견·계산 결과 또는 차단 사유 |
| 한계 | PDF 미포함, 추출·OCR·표·이미지 한계, 반올림, 미검사 범위 |

[원문 재확인 감사 기록](../output/skill-review/source-recheck-audit.json)은 표113개·그림51개의 목록, 실제 시각 확인109쪽, 원문 불일치·보완 근거와 스킬17개 파일의 당시 해시를 담는다. 표77개의 캡션이 있는 페이지를 확인한 것은 해당 표의 모든 셀을 검산했다는 뜻이 아니다. 파일 해시는 스킬이 수정되면 달라지므로 현재 파일과 비교하고, 과거 검사 결과를 현재 통과로 간주하지 않는다.

과거 `output/skill-review/game-balance-bible-numeric-audit.json`은 **84개 주장 그룹**을 대상으로 한 수치·공식 검수 범위를, `numeric-regression-results.json`은 예제 산술 재현 결과를 담는다. `multi-agent-compatibility.json`은 정본·링크와 당시 호스트 시험 상태를 담는다. 각 `PASS`는 그 파일이 기록한 범위 안에서만 해석한다.

> [!TIP]
> 변경 후에는 영향을 받는 장·참고 파일·공식만 좁혀 다시 확인한 뒤, 필요하면 수치 재현기를 실행해 결과 JSON 갱신 사실을 함께 기록한다. 원문 전체가 없는 상태에서는 원문 대조 완료라고 주장하지 않는다.

**완료 기준**

- [ ] 주요 수치·표의 원문 근거 또는 재확인 필요 사유를 구분했다.
- [ ] 설명용 예시를 독립 계산하고 단위·기간·확률·TTK 조건을 적었다.
- [ ] 공유 자원과 KPI의 모집단·분모·기간을 확인했다.
- [ ] 정본, Claude 링크, 17개 파일, 8개 장, 출처 지도를 확인했다.
- [ ] 호스트 결과 또는 명시적인 차단 사유와 실제 시험 범위를 남겼다.
