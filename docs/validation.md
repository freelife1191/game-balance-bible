## 근거의 세 종류

문장·수식·그래프를 아래 세 범주로 나눕니다. 서로 섞이면 책의 사실, 설명을 위한 가정, 프로젝트 제안 각각의 책임 범위가 흐려집니다.

| 구분 | 뜻 | 확인 방법 | 예 |
|---|---|---|---|
| **원문 근거** | 책이 실제로 제시한 정의·수치·사례 | 인쇄 쪽수, PDF 쪽수, 표·각주·적용 조건을 대조 | `피해=A²/(A+D)`라는 책의 나눗셈 예시 |
| **설명용 예시** | 개념을 설명하려고 새로 둔 값과 상황 | 새 예시임을 밝히고 산술·단위를 독립 계산 | `A=130`, `D=100`을 넣어 피해를 계산 |
| **실무 보완** | 프로젝트에 적용하려는 정책·권고 | 가정, 데이터, 목표 경험, 한계를 기록 | 로그 분포와 이탈 구간을 함께 비교 |

> [!NOTE]
> 책의 게임 사례와 시장 수치는 집필 당시의 맥락입니다. 현재 서비스의 기준으로 바꾸어 단정하지 않습니다. 설명용 예시가 맞더라도 책에 있던 값이라는 근거는 되지 않습니다.

원문 근거는 [원문 페이지 지도](../.agents/skills/game-balance-bible/references/source-map.md)에서 장·인쇄 쪽수·PDF 쪽수와 추출 한계를 확인합니다. 책의 전체 PDF는 현재 이 저장소에 포함되어 있지 않습니다. 원문을 다시 대조해야 하는 경우에는 합법적으로 접근 가능한 원문 사본으로 확인합니다. 스킬에 대조를 요청하는 방법은 [원문과 대조하고 싶을 때](troubleshooting.md#source-comparison)에 있습니다.

## 수치와 공식의 검증 순서

수식에는 기호, 단위, 적용 순서, 정의역을 함께 적습니다. `HP / 1회 실제 피해`는 **타격 수**이고, `HP / 초당 피해`는 **시간(초)**입니다. 단위가 다른 두 값을 같은 결론에 섞지 않습니다.

1. **원문·출처 대조** — 표의 행·열, 소수점, 부호, 분수, 반올림, 변수 정의를 확인합니다. 텍스트로 모호한 표·수식은 원문 PDF 페이지 이미지로 재확인합니다.
2. **전제 확인** — 확률이 독립인지 순차 판정인지, 보정이 가산인지 곱연산인지, 기간과 모집단이 같은지 확인합니다.
3. **독립 계산** — 별도 식이나 계산기로 합계, 기댓값, 가중 평균, 누적값을 다시 계산합니다. 표시 반올림과 산술 오류를 구분합니다.
4. **경계값 확인** — 분모 0, 음수·범위 밖 확률, 0 소비량, 초깃값 누락, 공유 재화의 이중 사용을 검사합니다.
5. **판정 기록** — 원문 표기, 추출 오류, 설명용 예시 오류, 실무 가정 차이를 구분합니다. 원문 오기로 보이면 임의로 고치지 않고 근거와 정합 계산을 같이 남깁니다.

### 독립 사용 시험과 직접 검산

스킬 사용 시험에는 의도한 답을 미리 주지 않습니다. 스킬이 필요한 파일을 찾고, 가정과 단위를 밝히며, 풀이를 재현 가능하게 만드는지를 봅니다.

```text
$game-balance-bible
체력 101인 적을 한 번에 20씩, 초당 2회 공격한다.
필요 타격 수와 첫 타격이 0초일 때 처치 시각을 계산해줘.
사용한 가정, 단위, 관련 근거 파일을 밝혀줘.
```

> [!TIP]
> 위 사례의 직접 검산은 `ceil(101 / 20) = 6회`입니다. 첫 타격이 0초이고 초당 2회이면 간격은 `1/2초`, 처치 시각은 `(6−1)/2 = 2.5초`입니다. 이는 해당 사례의 산술·가정 확인이며 모델 응답 전체의 증명은 아닙니다.

### 재현 가능한 수치 회귀

프로젝트의 산술 검산 재현기(Python 표준 라이브러리만 사용)는 스킬 예시의 산술과 명시한 모델 불변식을 검증합니다.

```bash
python3 output/skill-review/numeric_regression.py
```

이 명령은 `output/skill-review/numeric-regression-results.json`을 **갱신**합니다. 실행 전후 변경을 검토하고 `status`, 실패 항목, `limitation`을 읽습니다. 현재 기준은 산술 단언 **64개**, 확률 격자 **1,331개 조합**, 피해식 동치 **24개**입니다. 이 재현은 전체 원문 판독이나 실제 호스트 호출을 수행하지 않습니다.

## 구조와 포함 범위

원본 스킬은 `.agents/skills/game-balance-bible`이며 Claude Code에는 다음 상대 심볼릭 링크 하나를 둡니다.

```text
.claude/skills/game-balance-bible
→ ../../.agents/skills/game-balance-bible
```

스킬 묶음은 Markdown 지식 파일 **16개**와 호스트 메타데이터 `agents/openai.yaml`을 합쳐 **17개 파일**입니다.

| 구성 | 수량 | 역할 |
|---|---:|---|
| `SKILL.md` | 1 | 호출 규칙, 8장 색인, 적용 원칙 |
| `chapters/ch01`~`ch08` | 8 | 프로세스·준비·전투·경제·검증·수익화·시각화·모듈화 지식 |
| `references/*.md` | 4 | 전투 공식, 경제 모델, 원문 페이지 지도, 질문별 자료 지도 |
| `glossary.md`, `patterns.md`, `cheatsheet.md` | 3 | 용어, 실무 절차, 빠른 참조 |
| `agents/openai.yaml` | 1 | Codex 호스트 메타데이터 |

**구조 확인 체크리스트**

- [ ] 원본 경로와 Claude Code 링크가 모두 존재하고 링크 대상이 원본 경로인지 확인합니다.
- [ ] 8개 장 파일과 참고 파일 4개가 빠지지 않았는지 확인합니다.
- [ ] `SKILL.md`의 장 색인과 실제 파일명이 일치하는지 확인합니다.
- [ ] 원문 페이지 지도에 장별 인쇄 쪽수·PDF 쪽수·추출 한계가 있는지 확인합니다.
- [ ] 새 내용은 원문 근거·설명용 예시·실무 보완 중 어디에 속하는지 표시합니다.

> [!IMPORTANT]
> 파일이 발견되는 것과 실제로 계산을 수행하는 것은 다릅니다. 구조 확인은 경로·링크·파일 구성만 확인하며, 로그인 상태나 호스트 런타임을 검증하지 않습니다.

## 수식·자원·KPI 점검표

### 전투·확률·처치 시간(TTK)

| 점검 항목 | 확인 질문 |
|---|---|
| 피해식 | `A`, `D` 등 기호의 뜻과 분모가 0이 될 수 있는 조건을 적었는가? |
| 적용 순서 | 고정 피해, 가산 보너스, 비율 보너스, 최종 배율의 순서를 고정했는가? |
| 확률 | `0≤p≤1`인지, 독립·순차·원탁 판정 중 어느 모델인지 밝혔는가? |
| 기대 피해 | 결과 확률의 합이 1인지, 미스·치명·관통이 겹치거나 누락되지 않는지 확인했는가? |
| 비율 정의 | 표 5.15의 1회 피해 비율과 표 5.13의 생존 턴 비율을 구별했는가? |
| 란체스터 비교 | 간이 비교식에 1회 대미지를 넣었는가? 헤비과금 1인이 동시에 상대하는 활성 유저 수(PVG) 추정을 실제 승률로 읽지 않았는가? |
| TTK | 타격 수와 시간 단위를 구분하고, 첫 타격 시각·공격 속도·회복·보호막 조건을 적었는가? |

### 경제·공유 재화

| 점검 항목 | 확인 질문 |
|---|---|
| 기간 | 일간·주간·시즌 누적을 같은 기준 기간으로 환산했는가? |
| 잔여량 | `생산−소비`와 초기 보유량을 포함한 실제 잔고를 구별했는가? |
| 공유 제약 | 동일 재화를 여러 기능이 동시에 쓸 때 총 공급을 초과 배분하지 않았는가? |
| 소비 0 | 잔여 비율의 분모가 0이면 지표를 정의하지 않거나 별도 처리했는가? |
| 기댓값 | 드롭 확률과 수량, 시도당·성공당 기준을 분리했는가? |

### 수익화·KPI

| 지표 | 반드시 맞출 조건 |
|---|---|
| ARPU·ARPPU·활성 유저 결제율(PR) | 분자·분모가 같은 기간과 같은 유저 집합인가? |
| LTV | ARPU, 이탈률, 집계 주기, ARPU·이탈률이 일정하다는 가정을 명시하고, ARPU로 읽는 근사가 원문 본문 식(평균 결제율)이 아닌 스킬의 해석임을 밝혔는가? |
| CPA | 획득 비용과 유입 유저의 귀속 기간이 같은가? |
| 비교 | 과금 수준·직업·레벨·유저군을 섞지 않고 분리했는가? |
| 회수 시점 | LTV와 구별해 코호트별 누적 수익·비용 및 이탈·유입 경로를 정의했는가? |

> [!NOTE]
> 수치가 매끈해도 목표 경험이 맞는지는 별도 플레이 시험이 필요합니다. 그래프, 전투력, KPI는 판단 재료이며 단독으로 밸런스를 보증하지 않습니다.

## 호스트 사용 시험

실제 호스트 시험은 **발견**, **지식 탐색**, **계산**으로 분리합니다.

| 시험 | 확인할 것 | 통과 기준 |
|---|---|---|
| 발견 | 새 세션의 목록·호출 경로 | `game-balance-bible` 이름과 원본 경로가 확인됨 |
| 지식 탐색 | 장 번호·주제 질문 | 관련 장·참고 파일과 한계를 밝힘 |
| 계산 | 답을 주지 않은 작은 문제 | 가정·단위·계산 순서가 직접 검산과 일치 |

> [!NOTE]
> `output/skill-review/multi-agent-compatibility.json`의 기록에서는 Claude Code가 스킬 **발견**에는 통과했지만 OAuth 세션 만료로 계산 시험이 `BLOCKED_AUTH`였습니다. Antigravity 계산 시험은 통과했으며 `936/11`(약 `85.0909`), 6회, 2.5초를 보고했습니다.
>
> 이는 당시 환경의 기록입니다. 이 기록 이후의 Claude Code·Antigravity 재실행 결과는 이 문서에 포함하지 않습니다. 새 세션·새 모델·다른 호스트에서도 자동으로 재현된다는 뜻이 아닙니다.

2026-10-12의 [Codex 실제 호출 기록](../output/skill-review/codex-host-smoke.json)은 Codex CLI 0.162.0의 읽기 전용 세션 **1회**에 대한 기록입니다. 기대 답을 제공하지 않은 요청에서 스킬 이름으로 원본을 찾고, 관련 장·레퍼런스를 읽고 Python으로 계산했습니다. HP 385, 타격 6회, 정확한 처치 2.5초와 초당 피해(DPS) 근사 2.525초, 월 ARPPU 194.8·ARPU 19.48·근사 LTV 97.4가 직접 검산과 일치했습니다. 실제 회수 월은 입력 부족으로 확정하지 않았습니다. Codex App UI·다른 호스트·전체 고급 예시의 시험은 포함하지 않습니다. 이 결과는 후속 원문 재검수로 스킬 자료를 보완하기 전 버전에 대한 기록입니다.

인증 실패나 권한 거부가 나면 결과를 `BLOCKED_AUTH` 또는 환경 차단으로 기록합니다. 토큰을 출력하거나 인증을 우회하지 말고, 원문 대조와 독립 계산처럼 가능한 검사를 계속합니다.

| 고급 5장 B: 공유 재화 | 레벨 4; 장비 우선 2단계·스킬 1단계, 소비 130·잔여 30; 가능한 정수 조합 10개 |
| 고급 8장 A: 모델 맵 | 10개 모델·소비/생산 분리·모델 8→4 피드백·전투 기본 모델의 필요 시 호출 |

**응답 정확성은 5/5 통과했지만 실행 증거는 별도로 판단했습니다.** 수치 예시 중 3개는 ‘도구로 검산했다’는 응답과 달리 이벤트에서 계산 호출을 확인할 수 없었습니다. 공유 재화의 실제 Python 검산은 조합 수를 처음 9개로 잘못 단언해 실패했습니다. 이후 조합 수를 10개로 수정해 재실행했고 최종 답변은 정확했습니다.

따라서 [실행 증거를 요구하는 후속 요청](advanced-usage.md#계산-결과를-실행-증거로-확인하기)을 보완했습니다. 해당 3개 계산을 후속 세션 1회에서 재검산해 Python의 실제 출력과 단언 통과를 확인했습니다. 처음 응답의 실행 증거 미확인 상태를 소급해 통과로 바꾸지는 않습니다. 전체 고급 예시·다른 호스트·실제 게임 결과의 검증은 아닙니다.

이후 스킬의 진입점·실무 패턴·질문별 자료 지도에도 실행 검산 조건을 반영했습니다. 개념 설명은 실행을 강제하지 않고, 실행 검산에서는 관측 출력·실패·미실행을 구분합니다. 조회·공유 재화는 조합 개수보다 비용 제약·목록·잔여량을 먼저 검증합니다.

보완 후 새 입력의 독립 세션 2개도 통과했습니다. 실제 Python 실행에서는 5일 기대 생산 15·분산 15·목표 달성 확률 76.26953125%, 공유 재화의 장비/스킬 2/1단계·잔여 0·가능 조합 8개를 확인했습니다. 계산 도구를 금지한 별도 요청에서는 7타·처치 2초를 식으로 확인하고 실행 검산과 실제 플레이를 미실행으로 표시했습니다. 입력·출력·독립 검수·스킬 17개 파일의 당시 해시는 기록의 `post_validation_refinement`에 있습니다. 과거 보고서의 해시는 각 시험 당시 버전으로 유지합니다. 이 절의 표본과 보완 후 시험은 모두 후속 원문 재검수로 스킬 자료를 보완하기 전 버전의 결과이므로, 현재 스킬 파일의 해시와 다를 수 있습니다.

## 보고서 읽기와 완료 기준

검수 결과에는 최소한 다음을 남깁니다.

| 항목 | 기록할 내용 |
|---|---|
| 대상 | 스킬 경로, 확인한 파일 범위, 원문 식별자 |
| 근거 | 쪽 번호·표·적용 조건, 설명용 예시, 실무 보완의 구분 |
| 계산 | 공식, 변수·단위, 기간, 가정, 독립 검산과 허용 오차 |
| 구조 | 원본 경로, Claude Code 링크, 17개 파일과 8개 장의 확인 결과 |
| 호스트 | 시험 프롬프트, 발견·계산 결과 또는 차단 사유 |
| 한계 | PDF 미포함, 추출·OCR·표·이미지 한계, 반올림, 미검사 범위 |

[원문 재확인 감사 기록](../output/skill-review/source-recheck-audit.json)은 표 113개·그림 51개의 목록, 실제 시각 확인 109쪽, 원문 불일치·보완 근거와 스킬 17개 파일의 당시 해시를 담습니다. 표 77개의 캡션이 있는 페이지를 확인한 것은 해당 표의 모든 셀을 검산했다는 뜻이 아닙니다. 파일 해시는 스킬이 수정되면 달라지므로 현재 파일과 비교하고, 과거 검사 결과를 현재 통과로 간주하지 않습니다.

과거 `output/skill-review/game-balance-bible-numeric-audit.json`은 **84개 주장 그룹**을 대상으로 한 수치·공식 검수 범위를, `numeric-regression-results.json`은 예제 산술 재현 결과를 담습니다. `multi-agent-compatibility.json`은 원본·링크와 당시 호스트 시험 상태를 담습니다. 각 `PASS`는 그 파일이 기록한 범위 안에서만 해석합니다.

> [!TIP]
> 변경 후에는 영향을 받는 장·참고 파일·공식만 좁혀 다시 확인한 뒤, 필요하면 산술 검산 재현기를 실행해 결과 JSON 갱신 사실을 함께 기록합니다. 원문 전체가 없는 상태에서는 원문 대조 완료라고 주장하지 않습니다.
